## Проверки

```bash
python3 -m unittest discover -s tools/blur-pilot-five -p 'test_*.py'
python3 tools/blur-pilot-five/validate.py --catalog /path/to/celikom-approved-snapshot.json --report /tmp/blur-five-audit.json
python3 tools/blur-pilot-five/validate.py --audio-check --report /tmp/blur-five-audio-audit.json
```

`--audio-check` скачивает пять файлов **только временно** из исходного публичного репозитория с pinned commit, проверяет размер, Git blob SHA-1, возможность декодирования, длительность, кодек и удаляет файлы. Никакое аудио не попадает в коммиты, артефакты или публичный хостинг. Это техническая проверка исходников, **не доказательство отсутствия блюра и не проверка прав**. CI не использует production credentials.

## Перед импортом в CELIKOM

1. Отдельно проверить живую БД на `tracks`/`track_replacements`, включая pending/rejected и иные Track ID той же записи; проверить расхождение продолжительности с соответствующим конкретным треком Яндекса.
2. Удостовериться в правах на размещение/трансляцию аудио: наличие файлов в открытом GitHub не даёт лицензии на музыкальные записи. При необходимости использовать отдельно полученные разрешённые пользователем версии. Не забирать медиа вслепую в нашу серверную библиотеку.
3. После подтверждения прав и качества поместить разрешённые MP3/WAV в *приватный* staging, затем штатными владельческими действиями `add-track`, `add-asset`, `link` создать только **pending** записи. Никаких массовых `approve`/`activate` без ручной проверки пяти песен. Сохранять возможность отзыва/отката.
4. Проверить, что все пять появились в админке и **ни одна не стала активной сама**; после модерации проверять Play/Pause/Seek браузера/Android/Windows в согласованное время, не затрагивая текущую работу разработчиков.

Пока это строго read-only пилот, **не импорт песен в production**. Если CI успешно проверит исходники, появится техническое основание для следующего контролируемого шага.
