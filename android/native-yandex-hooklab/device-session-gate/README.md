**Назначение:** отдельный, сугубо диагностический Android APK для владельца HONOR 50 и других разрешённых тестовых устройств. Не использует старую схему CELIKOM Test.50 и не является рабочей нативной аудиоподменой.

## Зачем

На пустом Android 11 эмуляторе официальная Яндекс.Музыка отказала во внешнем доступе к public MediaBrowser, поэтому тот результат не показывает, доступна ли сессия на **уже авторизованном и воспроизводящем музыку** устройстве. Настоящая проверка может быть выполнена в неизменённой установленной Яндекс.Музыке через документированные Android MediaSession APIs.

Две независимые ступени:

1. **«Проверить без дополнительных разрешений»** — только попытка соединиться с найденным **одним** публично экспортированным MediaService, затем считать **булевы флаги** разрешённых команд Media3.
2. **«Проверить активную сессию»** — по желанию владельца, после явного предоставления системного разрешения **«Доступ к уведомлениям»** (NotificationListenerService) через Android. По документированному контракту MediaSessionManager.getActiveSessions(ComponentName) право требуется для чтения токенов активных сессий; CELIKOM фильтрует только пакет `ru.yandex.music`, не читает сами уведомления. Через platform token проверяются playback action flags и через Media3 — лишь command flags.

**Внимание: разрешение «Доступ к уведомлениям» действительно очень широкое.** Android технически позволяет приложению с ним читать содержимое уведомлений. Конкретная версия Native Gate специально реализует пустые NotificationListenerService callbacks и не сохраняет/не передаёт содержимое. Разрешение совершенно необязательно. Если Android скрывает переключатель или блокирует его политикой безопасности, **не обходить блокировку**. После теста лучше отозвать разрешение в системных настройках.

## Что приложение НЕ делает

- Не подменяет источник и не выдаёт себя за оригинальный Яндекс.
- Не отправляет `play/pause/seek/setMediaItem/replaceMediaItem` в Яндекс.
- Не вызывает `getMetadata/getCurrentMediaItem/getQueue/getUri`, не собирает трек ID, аккаунт, токены, строки/заголовки/URI и медиа.
- Нет разрешений `INTERNET/RECORD_AUDIO` и никакой отправки на сервер; нет обновления/установки других APK.
- Не требует root, патча подписи, удаления официального Яндекса или отключения Play Protect.
- Не изменяет установленный CELIKOM, Test.50, Windows, сервер, БД, браузерное расширение.
- Никогда не трактует доступ к queue commands как доказательство source-before-decoder. Даже `CHANGE_MEDIA_ITEMS=true` — лишь факт платформенного права на некоторые команды; не доказательство прав на альтернативный контент и не полноценная нативная подмена.

## Проверка на устройстве (после выпуска подписанного APK)

1. Убедиться, что работает обычная установленная Яндекс.Музыка. Включить любой трек **внутри оригинального приложения**. Сохранять имя трека/аккаунт в диагностике не требуется.
2. Установить отдельный `CELIKOM Native Gate`. Он не заменяет ни Яндекс, ни CELIKOM Test.50.
3. Нажать **«1. Проверить без дополнительных разрешений»**. Запомнить код результата и флаги; допустим `NO_PUBLIC_SERVICE`, `PUBLIC_BIND`-варианты и т.д. Эта ступень не просит доступ к уведомлениям.
4. **Только при желании** проверить вторую ступень: открыть настройки «Доступ к уведомлениям» по кнопке, включить `CELIKOM Native Gate`, вернуться, нажать **«2. Проверить активную сессию»**. Сохранить код результата и пять Media3 flags. Если Android запрещает или предупреждает о «ограниченных настройках», НЕ обходить ограничение.
5. По завершении отключить доступ в настройках и при желании удалить только `CELIKOM Native Gate`. Яндекс и все пользовательские данные останутся на месте.

**Если даже на активной сессии нет доступной команды source/queue replacement** — публичный путь пока NO-GO. Если команды есть, потребуется отдельный исследовательский этап безопасной верификации настоящего source-before-prepare, и только затем код подмены. Флаги сами не открывают скрытый DataSource.
