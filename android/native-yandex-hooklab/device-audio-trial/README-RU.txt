CELIKOM Android A1 — BETA32 (HONOR 50 / Android 13)
28.11.2026. Приватная диагностическая сборка для владельца. Не stable/OTA.

Что показал BETA31 NAV52 TXT:
- CELIKOM получил одобренный подписанный источник audio/mpeg.
- Точный альтернативный DataSource был вооружён, открыт и возвращал байты.
- При этом запрос FileInfo у оригинального Яндекса продолжал использовать прежнее согласование: CODEC_CONFIG_AAC=FEW, CODEC_CONFIG_MPEG=NONE, ISSUER_CODEC_MP3_REQUESTED=NONE.
- В renderer-свидетеле были ENGINE_HOLDER_RENDERER_TYPE1=MANY и ENGINE_HOLDER_TYPE1_STATE_NOT2=MANY; чтение возвращало -3 (NOTHING_READ), а подтверждённого STATE_STARTED / -4 не было.

BETA32 устраняет конкретное несоответствие форматов:
- Для включённого owner-режима, только точного оригинального FileInfoApi и только трёх разрешённых тестовых trackId запрос @Query("codecs") меняется на "mp3".
- Метод отдельно проверяет реальные @Query("trackId") и @Query("codecs"), их типы и уникальность.
- Все остальные треки, owner-off, другие API и неоднозначные сигнатуры остаются без изменений.
- Сохраняется оригинальный плеер Яндекса; второй плеер не добавляется.

Это адресная правка согласования формата, а не доказательство слышимой подмены. Проверка звука на телефоне обязательна.

Короткое нажатие CELIKOM сохраняет TXT; удержание открывает меню проверки/входа CELIKOM. Ошибки конфигурации, сессии и активации различаются. Вход только по собственной учётной записи CELIKOM. Не меняем авторизацию Яндекса, сервер, каталог, подписанные разрешения, Windows, stable или OTA.

Установка:
- Установить BETA32 поверх BETA31 на существующий Honor 50.
- Не удалять CELIKOM и не очищать данные или кеш.
- Убедиться, что статус CELIKOM — ВКЛ.

Проверка:
1. Ramil / 10AGE — «Ау», альбом 38902809, track 144530503, сегмент 00:43–00:54.
2. Вторую песню, у которой раньше были пробелы в начале.
3. Обычным коротким нажатием экспортировать TXT после проверки обеих песен.

В новом TXT проверить:
- ISSUER_CODEC_MP3_REQUESTED — должен стать положительным для разрешённого трека.
- CODEC_CONFIG_MPEG — должен появиться, если Яндекс принял MP3-согласование.
- DATASOURCE_ARMED / AUDIO_OPEN / AUDIO_READ — маршрут должен сохраниться.
- LIVE_RENDERER_ALT_SOURCE_READ_SAME_CURRENT_PERIOD_NON_EOS — нужен для подтверждения, что те же альтернативные байты дошли до текущего периода; один только AUDIO_READ этого не доказывает.

Отдельно сообщить, был ли реально услышан альтернативный звук внутри оригинального приложения Яндекс Музыки. Не считать положительные счётчики доказательством звука.
