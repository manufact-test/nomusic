CELIKOM 0.3.22-probe, versionCode 23, package pro.celikom.nativeprobe.

This owned-app update preserves the original native audio diagnostics and persistent signing identity. New Java source replaces only the 0.3.17 addon dex. Original classes change only version constants. Original resources/catalogue are retained. The notification listener, framework-session enumeration, broad notification inventory, Accessibility and library probing are absent from the addon and manifest. No protection bypass or identity rotation is used.

Integrated bounded 12-minute run: direct Media3 current-player state, album constrained identity, private persistent album cache, metadata fallback with explicit confirmation for playback, existing CELIKOM HTTPS account login/email verification/refresh/logout, config+entitlement checks, exact-ID resolve, bounded private audio pre-download, validated source/server/file durations, owner-enabled automatic replacement within the 12-minute foreground run, pause/seek following, verified nonzero Yandex equalizer audio session only, source-specific DynamicsProcessing attenuation, stop/error/disconnection/headphone unplug restoration, one local TXT. No global volume changes, Yandex credentials, account scraping, microphone or audio capture. Passwords never persist; sessions use AndroidKeyStore AES-GCM. The API origin is the same published CELIKOM deployment used by extension 0.4.58. Activation is a separate explicit owner action and may start the account trial. Server failures and denied entitlement keep original audio.

Limits: this is an owner test build, not a production release. Device runtime and Play Protect acceptance require physical testing. Current API has no complete metadata-catalogue export endpoint: embedded historical own-catalogue snapshot stays correctly stale; it is not refreshed by changing its timestamp. Metadata matching cannot prove a globally unique source edition. Learned-metadata playback needs explicit per-track confirmation. Audio is transient, pre-armed preparation expires after 60 seconds, and files are discarded on stop/change/failure, not an offline playback entitlement. Signed URLs are checked against same origin, path, query and time bounds and redirects are not followed. Positive gain uses standard LoudnessEnhancer when available. Calls/audio focus depend on Yandex pausing its source; headphones unplug pause playback and retain the armed mode, awaiting source pause then resume. Hardware effect audibility/restoration and route behavior must be verified on the real device. No production server or repository mutation was performed.

Build: Python build_release.py with Android SDK36, JDK17, Apktool2.11.1, official Media3 common/session1.8.0, Guava33.3.1-android, annotation1.9.1. 108 deterministic engine assertions execute the actual ReplacementEngine against fake transport/audio adapters (fakes are not packaged as application code). Host tests also cover parsers, hybrid precedence, ambiguity, expired snapshots, cache, signed URL constraints, duration tolerances, stale/disconnected source and redaction. The baseline APK and private signing archive are deliberately excluded from the embedded source archive. Android build/signing tools are external build dependencies.

0.3.21 — regression repair from owner combined report 20261020-210948:
The phone emitted playing→temporary not-playing→playing around seeks. 0.3.20's fade callback treated temporary not-playing as source loss, disposed the decoder and downloaded the same audio again. Seek-complete also started audio without rechecking the latest source state. Both paths are repaired: source pause always silences/pauses the replacement immediately, retains the decoder and file, cancels pending fade work, and retains source attenuation for a 350ms grace interval. Sustained pause releases attenuation, not the decoder. Seek completion delegates to the latest state; it cannot start audio while the source is paused. Source disconnect, stale identity, lost effect control and playback error still restore the original.

Within the foreground run, up to three recently played private files (total <=60MiB) can be reused after a NEW successful authenticated resolve matching track, replacement ID, version, duration and format. A cache entry never provides entitlement or an offline mode. File durations are rechecked after decoder preparation. Stop, logout, service shutdown or entitlement rejection deletes cached files. Source transition retains only already validated audio; cancelled/incomplete downloads are discarded. Manual return disables further preloading until explicitly armed again.

Activation may wait for song identity and a verified Yandex equalizer panel attachment; no second activation tap is needed once those become available. Media controller polling now also reconnects when disconnected or when connected with no item for five seconds. First source-session attachment STILL requires the Yandex equalizer, and a session change still stops replacement. Broadcast session IDs are not promoted to trusted attachment IDs. No extra permissions were added. These changes do not claim the session-discovery production milestone is complete.

Validation: 92 actual-engine assertions with deterministic audio/network adapters, including short buffering pauses during seek/ramp, delayed seek-complete during pause, repeated rapid seeks, sustained pause/resume, cached return, new replacement version, denied entitlement, cache deletion and activation before Yandex.
