# CELIKOM website v5.14 — мобильный FAQ и полноценная навигация CMS

**Дата:** 18.10.2026. **Репозиторий:** `manufact-test/nomusic`, ветка `feature/api-range`.
**Развёрнуто:** только закрытый Hostinger staging, публичный запуск запрещён. Сайт https://lemonchiffon-narwhal-791953.hostingersite.com/ ; админка https://lemonchiffon-narwhal-791953.hostingersite.com/admin/ .

## 1. FAQ на мобильном

Системная серая полоса горизонтальной прокрутки категорий заменена на узкий 4px фирменный мятный индикатор прогресса под чипами. Индикатор отражает `scrollLeft / (scrollWidth-clientWidth)`, обновляется на скролле и `ResizeObserver`, не перехватывает нажатия/жесты, скрывается на десктопе и при отсутствии переполнения. В исходной v10 сетке, FAQ и анимации аккордеона никаких перестроек. Изменены `website/public/assets/css/v10/owner-v10-motion.css`, `website/public/assets/js/v10/owner-v10-motion.js`, версия css/js `?v=514` в `CmsV10OwnerMotion.php`.

Проверено в настоящем Chromium на согласованном HTML v10 при 320px, 390px, 1440px — [owner-motion run 39155933309 PASS](https://github.com/manufact-test/nomusic/actions/runs/39155933309).

## 2. Админка — целенаправленный редизайн навигации

Раньше 87 полей, 28 FAQ и все инструменты шли непрерывно один за другим. Теперь `/admin/` после входа отображает рабочий стол:
- **Обзор**: черновик (номер), текущая опубликованная редакция, количество FAQ, карточки разделов.
- **Тексты сайта**: 14 групп (SEO, шапка, первый экран, преимущества, процесс, сравнение звука, плеер, участие, прозрачность, FAQ-тексты, бонусы, установка, финал, футер), на экране одна группа за раз. Все 87 проверенных поля остаются в одном безопасном POST для `CmsDraftStore` и не меняют контракт версионирования.
- **FAQ**: фильтр по четырём категориям + все, поиск по названиям вопросов, отдельные формы редактора и добавления. Защищённые правила как и раньше только для чтения.
- **Медиатека**: отдельный раздел с приватными upload/selection.
- **Публикации**: отдельный раздел с публикацией и восстановлением и существующим подтверждением.
- Вертикальная тёмная боковая навигация на ПК, компактное горизонтальное меню на телефонах, светлый контент с фирменным мятным акцентом. Сохранение черновика и ошибки видны в любом разделе, в том числе после редиректов. Старые URL хэши `#faq-editor`, `#media-editor`, `#revision-editor` по-прежнему поддерживаются. При отсутствии JavaScript старые формы доступны последовательно.

Код: `website/public/admin/index.php`; новые `website/public/assets/css/admin-workspace.css`, `website/public/assets/js/admin-workspace.js`. Не менялись схемы БД, логика черновиков, CSRF, аутентификация, media, editor contracts и миграции.

**Фактически развернуто** в защищённый Hostinger с резервными копиями и командой rollback — [run 39156110969 PASS](https://github.com/manufact-test/nomusic/actions/runs/39156110969). Из SSH workflow подтверждены живой сайт 200 только с паролем, логин админки, ссылки на новые CSS/JS, работа реального A/B аудиоплеера и HTTP 401 анонимно для `/`, `/admin/`, `/?demo_audio=service`. Никакого публичного запуска.

**Изолированный CI на MySQL и Playwright**: responsive 320,390,768,1440, login, обзор, пять страниц, выбор одной из 14 групп, поиск/категории FAQ, safe draft save, preview, logout — [run 39155978534 PASS](https://github.com/manufact-test/nomusic/actions/runs/39155978534). После этого добавлено покрытие реального media upload+preview+restore для нового workflow; статусы новых запусков проверяются отдельно.

**Важное о тестах:** старый `Stage9MobileAdminBrowserAudit.py` утверждает, что на стартовой странице обязательно виден заголовок «Черновик текстов» и все 87 полей доступны как один длинный экран, поэтому после смены архитектуры стал устаревшим и предсказуемо падает. Его не следует использовать для приёмки новой навигации. Основной website CI заменяет этот browser step актуальным `OwnerCmsWorkspaceBrowserTest.py`, сохраняя все PHP/HTTP и CSRF/Mysql core tests и дополняя browser media-проверкой. Обновлённые статусы CI проверять перед релизом.

## Что проверить владельцу сейчас

1. Открыть `/admin/` и убедиться, что после входа виден компактный рабочий стол, а переход в конкретную группу реально показывает только её.
2. Открыть FAQ через меню, попробовать фильтры и поиск; можно редактировать только разрешённое.
3. Открыть сайт на мобильном, пролистать категории FAQ вправо/влево: под ними новая мятная полоска, системной серой больше нет.
4. Отдельно согласовать дальнейшие функциональные изменения/визуальные уточнения. Публикация в MySQL не равна публичному открытию сайта.
