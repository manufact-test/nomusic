Ему нужен **РЕАЛЬНО ДОСТУПНЫЙ ПО URL сайт CELIKOM и работающая `/admin/`**, чтобы войти со своего компьютера и самому менять тексты, FAQ и изображения, сохранять, смотреть предпросмотр и публиковать. Приоритет №1 следующего чата — **добиться работающего закрытого веб-стенда на домене**, а не снова подготовить очередной технический пакет. Владелец пока НЕ дал явного разрешения менять Hostinger; сначала согласовать любые реальные изменения хостинга/домена/БД и только после разрешения выполнить их.

## Текущий реальный статус, не путать с «сайт запущен»

- По Master-ТЗ **10 этапов**. Этап 1 — принят, дизайн v10 этапа 2 — утверждён. Этапы **3–8 технически реализованы и проверены CI, но не приняты владельцем**. Этап **9 — небольшая CMS технически написана** и работает в изолированных тестах (авторизация, 87 текстовых полей, FAQ, приватные изображения, SEO, черновики, preview, публикация, история/откат). **Она НЕ развернута для владельца, он ни разу не входил в рабочую /admin/**. Этап **10 не закрыт:** отсутствует установленная, доступная по URL пара «сайт + CMS», затем нужны QA, ручные правки, legal/права/SSL и контролируемый общий релиз. Не обещать, что всё «готово», пока пользователь не сможет зайти по ссылкам и редактировать.
- Рабочая реализация находится в GitHub под `website/`. **На хостинге сайт/админка еще НЕ развёрнуты нами как рабочий пользовательский URL**. Действующие `/` и `/admin/` защищены от открытия до приёмки: HTTP 503/noindex. Скриншоты в GitHub Actions — лишь артефакт CI, **НЕ результат, который владелец просит**.
- Отдельный большой проект **AI Site CMS** существует **в другом репозитории**; не ждать его завершения и не переносить в CELIKOM. Нынешняя CMS — компактный редактор **одного** лендинга, без универсального билдера и multisite.

## ДЕЙСТВИЯ ДЛЯ СЛЕДУЮЩЕГО ЧАТА (ПРАКТИЧЕСКИЙ ПЛАН)

1. **Сначала** проверить актуальный GitHub HEAD, `docs/website/MASTER-TZ.md` (§4/§8), `ROADMAP.md`, этот файл, `docs/website/HOSTING-ACCESS.md`, `website/README.md`, `website/public/index.php`, `website/public/admin/index.php`, `website/database/migrations/001_website_cms.sql`, `website/app/` и CI. Использовать имеющийся код, **не строить CMS заново**.
2. Подготовить **самый короткий безопасный путь к работающим URL**: отдельно защищённый стенд на домене/поддомене Hostinger с HTTPS, `noindex`, отдельной MySQL (не трогать живые базы), приватными PHP/медиа вне web-root, независимыми учётными данными и ограниченным доступом. Не выбирать между лишними вариантами, если очевиден простой надёжный. Проверить текущую инфраструктуру **только чтением существующих документов GitHub**; при необходимости запросить **отдельное прямое разрешение** на реальные Hostinger/домен/SQL действия.
3. **После такого разрешения — НЕ останавливаться на плане, а реально развернуть сайт + /admin/** и проверить в браузере: страница, авторизация владельца, изменение H1/CTA и FAQ → сохранение черновика → закрытый preview → тестовая публикация → восстановление предыдущей версии. До фактической проверки **НЕ сообщать, что URL работает** и не придумывать ссылку или реквизиты.
4. Передать владельцу **две реальные ссылки** — сайт и `/admin/` — и безопасные инструкции входа (не печатать пароли в GitHub, коде или чате), чтобы он лично оставил правки; по замечаниям быстро довести внешний вид и интерфейс. Скриншоты или ZIP не заменяют ссылку.
5. После ручной приёмки и подтверждения прав на popup/юридических текстов, SSL, резервной копии и rollback — по отдельному **явному согласию владельца** выполнить публичный совместный запуск. Приватный стенд ≠ публичное открытие сайта.
6. **СТОП дальнейшей архитектурной разработке:** не делать очередные release generations, обвязки offsite/KMS/fsync/SQL migration labs без обнаруженной необходимости. Старые тесты оставить. Документы обновлять после существенного результата либо просьбы владельца.
