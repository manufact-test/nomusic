## 4. Протокол обновления после каждого чата

1. Открыть мастер-ТЗ и существующий NEXT-CHAT, проверить фактический рабочий GitHub branch и последний принятый checkpoint.
2. Заменить только **текущий статус**, **текущую задачу** и **следующий шаг** на актуальные значения; не оставлять два несовместимых «сейчас».
3. Новые принятые решения, завершённые задачи, ключевые исправления, блокеры и риски **добавить в историю** с датой и ссылками на коммиты/файлы.
4. Не удалять принятые требования, причины архитектурных решений, доступные публичные пути, инструкции по безопасности, незакрытые ошибки и обязательства.
5. Исправлять устаревшие технические сведения только после проверки; старое значение можно отметить как заменённое с причиной.
6. Если работа не сделана, прямо писать «не сделано / не проверено», без ложной приёмки.
7. Версионировать checkpoint, обновлять ссылочный Excel, дать пользователю готовый новый файл и при необходимости короткий стартовый текст.
8. **Не помещать** в checkpoint, GitHub и Excel пароли, приватные ключи, токены и другие секреты.
