# CELIKOM Android A1 — два параллельных чата, один главный разработчик

**Утверждено владельцем: 11 ноября 2026.** Один главный разработчик (чат A) и один помощник (чат B). **Никакого независимого слияния помощником.** Цель — ускорить подготовку и проверку без конфликтующих коммитов и без выдуманного прогресса продукта.

## Одна основная ветка / два рабочих направления

**Главный — чат A**, владеет основной веткой `experiment/android-native-a1-lspatch-clone-loader0-20261111`, blocker [issue #41](https://github.com/manufact-test/nomusic/issues/41). На момент разветвления HEAD `8860c5c2eb44aa694e0ea7fad48f224db9af1503`, точный backup `backup/android-a1-art-sampling-evidence-docs-final-20261111`. Только он отвечает за native startup, MAIN `EXIT_SELF(0)`, изоляцию проблем Android/Manifest/Activity в безопасном CI, за проверку подлинной нативной UI и интеграцию результатов B. Дополнительная экспериментальная ветка `experiment/android-a1-parallel-boot-lifecycle-20261111` зарезервирована **только для исследований A** (не обязательна к использованию); A сам определяет, переносить ли безопасные изменения в основную A1-ветку.

**Помощник — чат B**, живёт исключительно в `experiment/android-a1-parallel-audio-contract-20261111`, созданной от того же SHA `8860c5c2eb44aa694e0ea7fad48f224db9af1503`, с задачей [issue #42](https://github.com/manufact-test/nomusic/issues/42). Его работа — независимый чистый контракт выбора источника и тесты; NO второй плеер, NO собственный injector/Stage B, NO декларация готового Yandex audio.

Внешние исходники из Windows W61, extension, backend и APK-конкурента разрешено **изучать read-only** в пределах прав и безопасной диагностики. Не переносить неподтверждённый код, не обходить DRM, авторизацию, подпись/Play Protect, не собирать секреты. Исходную структуру требований A1 не менять; Stage B только после owner-accepted audible Stage A.

## Обязательная передача B → A

1. **B работает автономно** в своей ветке, делает точный backup до существенных изменений, код/тесты/документ, запускает свою отдельную CI и фиксирует реальные результаты. Обязан указать SHA, перечень новых файлов, интерфейс, что проверено / что не проверено.
2. **B создаёт PR в основную A1-ветку, но НЕ MERGE.** В [issue #42](https://github.com/manufact-test/nomusic/issues/42) оставляет ссылку на PR, итоговый SHA, CI и короткий handoff. Если PR технически недоступен, обязательно публикует SHA и пошаговый план переноса, не трогая основную ветку.
3. **A — единственный интегратор.** На свежем HEAD создаёт backup и при необходимости временную интеграционную ветку, читает PR и issue #42, проверяет API и безопасность, запускает все тесты A+B. Может принять только чистую модель и тесты до починки native boot; включать реальную подмену в Yandex нельзя до соответствующих stage gates. В случае конфликта интерфейса возвращает B на доработку.
4. A самостоятельно переносит проверенные результаты в основную A1-ветку, обновляет один authoritative handoff, оставляет обе issue с фактическим статусом. **B никогда не пушит в основную A1-ветку**.

**Взаимодействие двух отдельных чатов НЕ автоматическое.** GitHub issue и PR служат общей памятью, пользователь может принести ссылку или команду A «забери готовый PR помощника». Без такого сообщения или нового запуска чата работа не выполняется в фоне.

## Проверяемый status на момент деления

- Signed original Yandex 2026.10.3 five splits стартует на Android13 Redroid, MAIN alive/Activity resumed.
- Три независимо подписанных clone layout (five splits, merged direct, merged LSPatch0 zero modules) **MAIN `EXIT_SELF(0)`**. По точному PID у каждого два self-exit цикла; `IllegalStateException` в логах перед смертью, **причинность не доказана**.
- Собственный ARM LSPatch hook в собственном тестовом приложении — PASS, но не в нативном клоне.
- ART 599184 records × 14 + 32 bytes достигли предела 8 MiB; отсутствующие методы в неполной трассе не доказывают, что они не вызывались. Sampled 10ms ART trace не получен (0 bytes). Повторы этих CI без новой гипотезы запрещены.
- **Stage A = NO-GO, Stage B = locked.** UI/audio/owner Play Protect/audio acceptance не пройдены. Никаких APK на HONOR, никакого обращения в Яндекс.
