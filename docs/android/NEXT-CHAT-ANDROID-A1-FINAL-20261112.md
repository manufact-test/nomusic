**Каким должен быть продукт:** один отдельно устанавливаемый CELIKOM APK с **полностью нативным интерфейсом Яндекс.Музыки**: вход в Яндекс, библиотека, плейлисты, Моя волна, все обычные функции. Один **родной Яндекс-декодер**; CELIKOM меняет только источник для разрешённой альтернативной записи до native `prepare`. Штатная Яндекс.Музыка остаётся отдельно на HONOR 50 Android 13. **Никаких** WebView, самодельных/двойных плееров, отдельной музыки поверх, подмены настоящего входа/Passport/DRM или скрытого изменения устройства владельца.

- Проверены **все 8 661 не-подписные APK entries** byte-for-byte; добавлен **отдельный наш, честно подписанный SourceStamp**, 16/16 crypto PASS, own-signed app + source stamp 16/16 install PASS, MAIN по-прежнему **FAIL** [CI 43173312016](https://github.com/manufact-test/nomusic/actions/runs/43173312016). Никакого APKEditor, переименования, LSPatch или обхода подписи в данном A/B.
- Android PackageManager grants в этом same-guest A/B: **30/30 requested**, **15/15 granted**, `READ_CREDENTIALS` GRANTED в обоих, **0 различий**; отдельно подписанный MAIN всё равно падает [CI 43174180541](https://github.com/manufact-test/nomusic/actions/runs/43174180541). В самом последнем заходе исправили ещё две границы: **нельзя** принимать `durationMs<=0` при коротких треках, **нельзя** превращать посторонний объект или число в `editionId` через `String()`. Отбрасывание identity оставляет оригинальный источник. Новые и старые регрессионные **34/34 PASS** [CI 43176180946](https://github.com/manufact-test/nomusic/actions/runs/43176180946). Это source-only проверки, **не** live Yandex source swap.
- PHP `ResolveService` пока не даёт авторитетных `albumId/editionId` для всех сценариев. Нельзя выдумывать аттестацию или считать, что синтетический model PASS означает реальный звук.

**Самый важный следующий шаг:** **не запускай ещё один одинаковый signer/SourceStamp/ZIP/permission CI**. Ищи **реально новую, доказуемую native in-process execution surface** под отдельно подписанным CELIKOM (не нарушая подтверждённые security/auth/DRM/Play Protect границы). Без подтверждённого host/bridge нельзя честно сделать один Яндекс-декодер, и нет смысла давать владельцу APK. Изучи существующие native source-adapter наработки только для проверки возможного host, а не для новой очереди синтетических «успехов». Если новое обстоятельство найдено — сразу используй готовый source contract на точном `trackId+editionId+generation`, далее проверь реальный native UI/логин/Мою волну/выбор audio source и акустически pause/seek/Next/Stop/Range.

**Правила владельца:** **больше вообще не предлагай обращаться к Яндексу за разрешением** — он это много раз окончательно отверг. Не обсуждай это в качестве плана. Не отключай Play Protect, не фальсифицируй подписи, не копируй закрытый модуль конкурента. **Stage A NO-GO** до настоящей работающей нативной сборки и прослушивания у владельца; **Stage B LOCKED** до его акустического одобрения. Затем сам напомни, что Stage B — заменить временный LSPatch собственным адаптером.
