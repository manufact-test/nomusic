## Precisely one next boundary
NAV44 keeps the unchanged original renderer/player, same callback, same queue and late Flow guard. At most three attempts per exact holder/source weak pair, it:
1. Reads the same original PlaybackInfo current MediaPeriodId and its UID plus two ints, current original Timeline and current active holder;
2. Uses original signed `Timeline.getPeriodByUid(uid, Period)` to get a Window index and `Timeline.getWindow(index, Window, 0)` to get the original MediaItem reference;
3. Reads the exact original `LiLb` source MediaItem field proved by its **pure declared getter**, but only from the unique original source matched to the same scoped tCa/late Flow TrackWrapper;
4. Requires a stable second snapshot of PlaybackInfo, PeriodID, Timeline and live SLOT_B before classifying `==` Java reference identity. Only classifies `SAME_REF`, `DIFFERENT`, `UNAVAILABLE`, or `SLOT_CHANGED`—never exports a value.

The three original private field references and one source getter field are built ephemerally inside signed XAPK CI; class/method signatures are fixed and type-checked at runtime. Only this new private target can enable the additional observation; missing or drifted original targets fail closed. No new hook, no original method interception, no network or playback mutation, no media or secrets export.
