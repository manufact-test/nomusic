## Гипотеза
Время cold join ограничивает одиночное скачивание целого MP3, а не только время принятия/реалайнмента аудио. Сервер CDN иногда допускает HTTP 206 Byte Ranges: запросить 4 части параллельно, собрать в staging-file и передать MediaPlayer только полное проверенное содержимое. Вмешиваться в звук/владельца/seek нельзя. Ускорение зависит от сети и лимитов CDN и **не гарантируется**.

## Реализация Test.22
- Новый addon/src/pro/celikom/nativeprobe/identitydiag/FastAudioTransfer.java только для priority=current. lookahead продолжает прежний AudioTransfer.copy.
- 1-байтовый range preflight; только при 206, правильном Content-Range и сильном ETag, размере 1–30 MB, identity encoding. Дальше 4 ranged GET с If-Range; каждый требует 206, тот же strong ETag, точные Content-Range и размер части.
- Потоки записывают в непересекающиеся диапазоны staging-file. После успешного окончания всех частей staging файл перемещается в финальный; частичный файл никогда не отдаётся декодеру.
- Если Range не поддерживается, сервер/ETag изменились или HTTP ошибся, падаем назад на **существующий последовательный AudioTransfer.copy**. При отзыве playback lease/смене трека задача отменяется; активные соединения закрываются.
- Лог replacement_fast_full_file_transfer с mode parallel_verified либо serial_fallback_<reason>, временем и количеством байт. Лог replacement_download остаётся для базового сравнения.
- Не добавлять Accessibility/MediaProjection/VPN, не поднимать второй аудио-наблюдатель, не возвращать BufferedAudio потоковое воспроизведение.
- Нельзя вводить непроверенный автоматический deadline для сериализации и таймингов: измерить на устройстве.
