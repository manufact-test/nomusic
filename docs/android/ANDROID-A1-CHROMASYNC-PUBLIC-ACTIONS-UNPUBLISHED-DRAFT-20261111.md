# CELIKOM A1 — запуск точного ChromaSync на бесплатном публичном GitHub Actions без публикации APK

Дата: 11.11.2026. Подготовлено в отдельной экспериментальной ветке `experiment/android-a1-public-draft-arm13-20261111`; **основная ветка Android A1, Test.50, Windows, расширение, сервер и телефон владельца не изменены**.

## Зачем этот вариант

- Репозиторий `manufact-test/nomusic` публичный; стандартные GitHub-hosted Actions в публичном репозитории бесплатны и не тратят квоту частных репозиториев в 2000 минут.
- Бинарник ChromaSync **не помещать в Code/коммиты и не выпускать как опубликованный Release** — там он станет общедоступным, удаление позже не отзовёт уже сделанные копии.
- Достаточно **неопубликованного черновика GitHub Release (Save draft)** в существующем публичном репозитории. По GitHub Docs черновики доступны только аккаунтам с правами записи. Исполняющий workflow использует `contents:write` исключительно для доступа к черновику. Это не делает репозиторий приватным. Логи Actions остаются публичными — поэтому никаких бинарных файлов, логинов, токенов, стеков и исходного контента в них не публикуем.
- Отдельного приватного репозитория, сервера или GitHub Actions Secrets не требуется.

## Что сделать владельцу ОДИН РАЗ через браузер

1. Открыть **https://github.com/manufact-test/nomusic/releases/new** (важно: именно `nomusic`).
2. В поле `Choose a tag` ввести **`a1-chromasync-301-unpublished-test`** и выбрать создание нового тега для релиза.
3. Название релиза любое, например `CELIKOM Android A1 — ChromaSync private draft test`.
4. Перетащить **точно `ChromaSync-Clone-3.0.1.apk`** в поле прикрепления *release assets*. Это файл около 98 MiB, 102 572 843 байта.
5. Нажать строго **Save draft / Сохранить черновик**. **НЕ нажимать Publish release.** Не нужно менять репозиторий, искать папку или создавать Secret.
6. Сказать ведущему чату **«Черновик с APK сохранил»**. Ведущий самостоятельно делает небольшой push в экспериментальную ветку (по уже подготовленному path-trigger), проверяет CI, читает результаты и обновляет issue #41.

Если интерфейс не позволяет сохранить загруженный файл в черновике, не публиковать APK наугад; сообщить о проблеме.

## Уже подготовленный запуск

Workflow: `.github/workflows/android-a1-chromasync-draft-arm13.yml`; ветка `experiment/android-a1-public-draft-arm13-20261111`.

- Триггер: `push` в эту экспериментальную ветку на изменения самого workflow или `docs/android/ANDROID-A1-CHROMASYNC-DRAFT-ARM13-RETRIGGER-20261111.md`. Пользователь не должен искать кнопку Run workflow на основной ветке.
- Сначала 13 синтетических тестов наблюдателя, затем REST-проверка `draft==true`, tag, имени и размера прикреплённого APK. Отсутствие черновика вызывает `UNPUBLISHED_DRAFT_NOT_READY`, а не ложный Android PASS.
- На настоящем ARM64+ARMv7 Android13 Redroid через GitHub Actions `ubuntu-24.04-arm` получаем APK из неопубликованного GitHub Release через `gh release download` (с независимым REST fallback), проверяем `sha256=4e6edb1c471f6b3715eae4c0a35f0bd898b0daaa87f3f8fb3ba0b20d1638b53d` и размер `102572843` **до установки**.
- APK конкурента тестируется **сначала отдельно** (Android PackageManager, MAIN и 16 секунд одного PID в resumed Activity). После этого в другом совершенно чистом госте ставятся 5 официально подписанных split APK оригинального Яндекса 2026, затем проверяется попытка установки ChromaSync рядом, включая `INSTALL_FAILED_CONFLICTING_PROVIDER` и другие ошибки.
- Сохраняем только классифицированные статусы установки и жизненного цикла. Гость и локальные бинарники удаляются. **Не устанавливаем на HONOR 50 владельца, не подменяем подпись, не меняем Passport/DRM/Play Protect, не переносим LSPatch level 2 либо чужой модуль в CELIKOM.**
- Успешная установка и 16 секунд жизни MAIN — лишь доказательство короткого нативного старта, не воспроизведения, логина, UI пикселей, Play Protect или работоспособности всей Яндекс.Музыки.
