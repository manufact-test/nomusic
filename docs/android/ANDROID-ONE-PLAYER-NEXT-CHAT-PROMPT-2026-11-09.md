# First message for the NEXT chat — CELIKOM Android one-player architecture

Привет! Продолжаем **CELIKOM Android**, GitHub `manufact-test/nomusic`. Владелец утвердил **смену архитектуры вместо очередной Test.77**: нужен пользовательский сценарий «включил CELIKOM → открыл привычную Яндекс.Музыку → слушаю оригинальные версии без цензуры», неважно, будет CELIKOM эквалайзером, модулем или отдельным управляющим приложением. Главное — **один реальный проигрыватель для текущего трека**, нативные Play/Pause/Seek/Next без задержек, корректный старт, безопасная нормальная установка с **включённым Google Play Protect**, желательно без root. Допускается исследовать совместимый изменённый клиент Яндекса; **нет обязательного требования не трогать официальный APK**, но нельзя незаметно менять установленный Яндекс пользователя или просить отключить защиту.

**Начни с ветки** `research/android-single-player-inprocess-20261109` и обязательно прочитай:

1. `docs/android/ANDROID-ONE-PLAYER-ARCHITECTURE-FEASIBILITY-2026-11-09.md` — основной утверждённый технический маршрут, конкуренты, реалистичные риски, шаги Gate 0–4.
2. `docs/android/ANDROID-TEST76-FINAL-HONOR-FORENSIC-2026-11-09.md` — последняя диагностика владельца. Test.76 **не исправил практическую проблему**: шесть `SecurityException` до подключения ~14.3с; «Папиросы» заменились, RASKOL ID 42884423 нашёлся и файл подготовился, но Media3 застыл BUFFERING на 0 до конца записи; framework witness **91/91 disabled**, поэтому новый Test.76 восстановительный механизм *вообще не запускался*. Сборочный CI Test.76 PASS — это НЕ проверка на телефоне. Не надо опять просить этот лог или собирать Test.77.
3. `docs/android/ANDROID-0385-NEXT-ARCHITECTURE-GITHUB-RESEARCH-2026-11-04.md` и верх `docs/android/NEXT-CHAT.md`; старый запрет на patched Yandex client **отменён решением владельца от 09.11**.

**Изученные варианты:** [ChromaSync Mobile](https://github.com/Desai0/ChromaSync-Mobile) — нужная модель: модуль *внутри* совместимого Android Яндекса, без root через on-device patcher, но публичный GitHub содержит **только README** (нет исходников для копирования, Play Protect не гарантирован). [YM Liberty Android](https://github.com/gagayhhad-tech/ym-liberty-android) — открытый самостоятельный клиент, `android_app/assets/www/yandex.js` получает `trackId` и подставляет альтернативу до запуска; лицензия GPLv3, нельзя слепо переносить код в закрытый CELIKOM. [YaMusicTabs](https://github.com/daanqq/YaMusicTabs) — реальный in-process Android-hook, но только перестановка вкладок и версионная зависимость; [YaMusicLsposed](https://github.com/windyx0/YaMusicLsposed) требует root. ПК PulseSync/FckCensor — рабочий *Electron*-паттерн, не прямой Android механизм.

**Твоё задание, приступай без лишних вопросов:** сначала проведи **Gate 0 + Gate 1**: исследуй и проверь реальный, воспроизводимый, безопасный путь in-process интеграции в совместимом Android-клиенте. Закрепи зависимости, исходники, версии, лицензии, способ сборки, пакет/подпись и необходимые разрешения, план установки с Play Protect ON. Подготовь **отдельный прототип в собственной изолированной ветке**, вначале read-only: показать **подтверждённый оригинальный каталоговый Yandex track ID** (не внешний Media3 alias) и точку выбора источника именно одним проигрывателем. Покажи, как на RASKOL/«Дым» нативные Play/Pause/Seek/Next будут попадать напрямую в этот один плеер. Далее, только при подтверждённой реализуемости, подключи ОДИН заведомо разрешённый тестовый альтернативный файл **до начала проигрывания**, с безопасным fallback к оригиналу. Предварительный локальный кэш — плюс; не делай двухплеерных кроссфейдов одной песни.

**Безопасность/границы:** не меняй стабильный Android `pro.celikom.nativeprobe`, Test.50 эталон `backup/android-test50-exact-source-owner-accepted-20261108`, сервер, базу 1426 версий, админку, браузерное расширение и ПК; не запускай Play Protect bypass, root, скрытую инъекцию, сбор чужих OAuth/паролей, деактивацию защиты, не скачивай/публикуй проприетарный Яндекс APK в GitHub. Для проверки переустановки нужен запасной телефон/эмулятор и разрешение владельца перед любыми действиями с официальным приложением. **Play Protect approval ≠ Google Play Store publication**. Если нет корректного пути для A, честно дай `NO-GO` и сравни самостоятельный клиент B (полный функционал Яндекса — отдельный риск). Не считай любой фиктивный Media3 demo доказательством Yandex integration.

**Контроль:** реальные две-три песни: «Дым» Лёша Свик, RASKOL «Нас не понимают вообще», обычная; проверка точного ID/версии, первой загрузки и кэша, паузы, seek, Next, радио/рандома, оригинального fallback, установки Play Protect ON. На успешность в телефоне не ссылаться без реального теста. Сначала использовать статические проверки и GitHub CI, телефон просить проверить лишь когда есть конкретный прототип.

**Результат этого чата:** не километровый отчёт, а: что найдено/реализовано, ссылка на ветку и тесты, подтверждённые ограничения и требуется ли **одно** конкретное действие пользователя.
