# CELIKOM Android A1 — актуальное решение владельца и источник APK (12.11.2026)

**Приоритет:** решение владельца в текущем разговоре важнее устаревших формулировок старых инженерных заметок. Это документ об актуальном плане, не о готовой сборке.

## Что на самом деле требуется

- Продукт: **один CELIKOM Android APK**, отдельный от штатного установленного Яндекса; внутри — привычный **нативный интерфейс Яндекс.Музыки** (авторизация, поиск, библиотека, Моя волна, плейлисты, родное управление).
- Только для одобренного каталога CELIKOM менять **источник аудио штатного единственного декодера**; никакого второго собственного музыкального плеера, WebView-клона либо переключения приложений. Декодер уже есть в хосте Яндекса; искать отдельный не требуется.
- **Этап A: LSPatch разрешён и выбран владельцем.** Владелец прямо разрешил попробовать техническую совместимость, включая конфигурацию уровня **2** по примеру ChromaSync. Запрет на уровни LSPatch 1/2 и абсолютное требование `sigBypassLevel=0` были дополнительными инженерными ограничениями из старых заметок, **не решением владельца; отменены для текущего исследования**. Не возвращаться к нулевому уровню «потому что так записано», если это мешает цели.
- **Этап B** — собственный независимый механизм вместо LSPatch **только после** работающей и принятой владельцем версии A.
- Принятый Test.50 и официальная установленная Яндекс.Музыка на HONOR сохраняются. Прототип сначала проверяется отдельно в CI. Способ реализации проверять на фактической работоспособности, без фиктивных PASS.
- Техническая возможность локального эксперимента не равна подтверждённым правам на распространение чужого APK, учетным данным или гарантии Play Protect. Не выдавать неподтверждённое за решённое. Это не повод подменять пожелания владельца придуманных «запретов».

## Точная причина недавней остановки

Есть две **разные** входные версии:

**A. ChromaSync 3.0.1 конкурента**, файл уже предоставлен владельцем:
- SHA256 `4e6edb1c471f6b3715eae4c0a35f0bd898b0daaa87f3f8fb3ba0b20d1638b53d`.
- Нативный встроенный Yandex 2025.10.4 #120.1rur, внешний LSPatch metaloader + injector, конфигурация `sigBypassLevel=2`.
- На реальном ARM13 его полный APK продержался **75 секунд 25/25** MAIN/RESUMED, а извлечённый один `origin.apk` без обёртки не продержался. Реальный дифференциал [CI 43081123928](https://github.com/manufact-test/nomusic/actions/runs/43081123928). **Это не доказывает, что одна цифра 2 достаточна, а также не доказывает аудио/авторизацию конкурента.**

**B. Наши исходники:**
- **2026.10.3 #170gpr, 5 splits**, прежний A1 pipeline `clone_native_identity_phase2_ephemeral.py`: требует exact XAPK **60 433 885 байт**, SHA256 `918bd50599dc6a942e190a409303e843b83dcb6d11b90b03c00240331333cf84`.
- Pipeline скачивал `https://d.apkpure.com/b/XAPK/ru.yandex.music?version=latest`. По состоянию на 12.11.2026 слово **latest** уже не гарантирует старую exact версию! В experiment `experiment/android-a1-independent-sig-compat-arm13-20261112` LSPatch2 был добавлен, но [CI 43189751753](https://github.com/manufact-test/nomusic/actions/runs/43189751753) оборвался на `PINNED_ARCHIVE_CHANGED` **до формирования и запуска 2-level APK**.
- В коротком последующем заходе добавлен **preflight до запуска ARM Android** и повторное использование проверенного XAPK вместо второго скачивания с меняющегося URL. [CI 43195260815](https://github.com/manufact-test/nomusic/actions/runs/43195260815): исходный 2026 mirror теперь явно помечен `PINNED_2026_SOURCE_UNAVAILABLE` **до загрузки ARM-гостя**. Это подтверждает недоступность старого fixed XAPK через данный dynamic URL, а НЕ неработоспособность LSPatch 2. Отладку скачивания `latest` по кругу прекратить.
- **Подлинный оригинальный publisher-signed 2025.10.4 #120.1gpr**, 16 splits, УЖЕ доступен в **неопубликованном** GitHub Release draft: ID `442137464`, tag `a1-yandex-2025-gpr-private-test`, asset `736739728`, имя `yandex-music-2025-10-4-120-1gpr.xapk`, размер **45 961 661 байт**, SHA256 `8e43be8900d28ee92c8e315ed07069568858bfd4a593757fba9d276bd0c54053`. Его 16 issuer-signed splits **были криптографически проверены**, оригинальный MAIN **75с 25/25 PASS** на ARM13. [CI 43091414430](https://github.com/manufact-test/nomusic/actions/runs/43091414430). Это **другой** релиз, 16 вместо 5, поэтому нельзя просто подставить его в старый 5-split pipeline и написать PASS.
- 2025 GPR не тождественен конкурентскому RUR, и до проверки нельзя утверждать, что у них идентичные внутренние точки аудиозамены.

## Что реально сделано в GitHub

`experiment/android-a1-independent-sig-compat-arm13-20261112`:
1. В собственном экспериментальном clone pipeline введён **только для отдельной ветки** режим LSPatch `-l 2`; исходный zero-mode pipeline и основная A1 не изменены. Успешны структурные тесты, **не runtime**.
2. Выявлена динамическая ссылка `latest` как причина невозможности повторить точный старый 2026 source.
3. В CI input verified **до** поднятия ARM13; корректный input затем переиспользуется в clone builder, исключая дрейф между двумя скачиваниями. Несовпадение считается явным отсутствием входного архива, а не «LSPatch не работает». Это рабочее исправление диагностического маршрута, не готовый APK.
4. Документация зафиксирована согласно **текущему** решению владельца, без самовольного запрета сигнатурной совместимости.

## Следующая основная задача

**Приоритет — новый узкий 2025 A1 pipeline на имеющемся ПОДЛИННОМ GPR, а не пустые аудиоконтракты и попытки оживить 2026 `latest`.** Необходимо корректно обработать 16-split signed source (отдельная ветка/метод, не выдавать 16 за 5), собрать самостоятельно подписанную копию с собственным package ID, встроить LSPatch metaloader и протестировать `-l 2` на disposable ARM13. Параллельно сравнить с `-l 0` **при одинаковой 2025 базе**, чтобы понять реальную причинность. Определить хотя бы фактическое MAIN/RESUMED/отдельную установку рядом с оригиналом, затем собственный CELIKOM source модуль, после — звук/Next/pause/seek/MyWave и проверка владельцем на HONOR.

Нельзя переносить без проверки код чужого injector или называть запуск успешным без реальных UI/аудио доказательств. На момент этого документа: **Stage A не подтверждён, рабочей пользовательской APK нет**.
