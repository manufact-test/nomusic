# CELIKOM Android A1 — ранний оригинальный Track+Album на Player source setter, 20.11.2026

## Где и что изменили
Ветка `experiment/android-a1-metrica-init-state-observer-arm13-20261112`, исходная база `b5917cecf871dbd140e82e62a346fefc01327a02`, runtime commit [55c73a2e](https://github.com/manufact-test/nomusic/commit/55c73a2e2eeed9c5050302c2bd4e086a94610033).

В `StageBAudioEvidence` добавлен `exactCreatorTrackAlbumBeforeSourceSet(wrapper)`. Метод возвращает именно creator-owned original Java `Track+Album` по уникальному рождению `tCa` в подписанном оригинале даже **до** позднего Track Flow. Требуются оригинальный creator scope, неизменный Album и уникальный wrapper; потеря refs, конфликт и неизвестный wrapper означают null. Строковые поля/ID не читаются.

В `NativeRendererStreamEvidence` добавлен ранний pending `EarlyOriginalSourceFrame` с оригинальными Java Track, Album, source и монотонным epoch. Сигнал на `androidx.media3.exoplayer.d.e(Sl6,long)` выдаётся **перед** `chain.proceed()`, но consumer не установлен, поэтому никакой alternate не применяется. Вложенные source setter, изменённое поколение, несоответствующий scope или исключение проваливаются fail-closed. Ранее наблюдение source производилось до результата оригинального setter; теперь `onNativePlayerSourceSetter` фиксируется только **после** успешного `chain.proceed()` (сам original вызван один раз).

Это перенос доступных **объектных ссылок** на более раннюю границу выбора source, не доказательство семантических идентификаторов, edition, real pre-prepare или звучащего PCM. `NativeReplacementLifecycle` пока законно не может выбрать alternate.

## Важный оставшийся барьер
Точно подтверждённая в signed 2025 оригинале `FileInfoApi(trackId)` пока **не доказана** происходящей от того же исходного `Track` при всех ветвлениях; `albumId` / `editionId` и текущее native selection generation не подтверждены. Оригинальный source setter может выполняться до renderer, но **порядок относительно настоящего decoder prepare не доказан**. Нельзя переносить позднее renderer evidence на pre-prepare и нельзя допускать подмену без этих доказательств.

`CELIKOM_REPLACEMENT=NOT_CONNECTED`; `IDENTITY_STATUS=STRUCTURAL_ONLY`. Следующий шаг — соединить эти точные исходные Java refs с семантическими ID и исходным descriptor на верифицированном pre-prepare callsite. Unknown → ORIGINAL. Не выпускать диагностический APK только ради счётчиков.

## 20.11.2026 — subsequent source lifecycle implementation

- [50f6d6c2](https://github.com/manufact-test/nomusic/commit/50f6d6c267e8250cff1911195cd663d4957bacf8) broadens the **same exact original creator** early setter seam to both source ordering cases: Track in original Flow before `tCa` creation, or creator Track appears in original Flow later. The only durable link is weak original Track/Album/source from an original setter that actually returned; after Next, another setter, source mismatch, clock generation mismatch, nested original setter or Album conflict the old link cannot be used. No IDs, URLs or audio are inferred from object equality. [JVM #44697491917 SUCCESS](https://github.com/manufact-test/nomusic/actions/runs/44697491917), [clone-only ARM13 #44697491867 SUCCESS](https://github.com/manufact-test/nomusic/actions/runs/44697491867); publisher-first [#44697491883](https://github.com/manufact-test/nomusic/actions/runs/44697491883) pending verification when this text was committed.
- [355af97a](https://github.com/manufact-test/nomusic/commit/355af97aeee6819c0505eda7306a6b25ae243acf) then [5cabef07](https://github.com/manufact-test/nomusic/commit/5cabef071afa6e474eba3883b39ab8331ec232d0): existing pure-Java `NativeReplacementLifecycle` supports reserving the ORIGINAL generation before semantic IDs exist, certifying later **only if an exact, numeric Track ID and complete album/edition are independently proven for the same original selection**. The resolution budget is anchored to original selection time, not certification time. When original pre-prepare arrives before proof, it seals ORIGINAL and rejects all late upgrades. STOP, old generations, duplicate certification and time discontinuity are rejected. Dedicated [Java CI #44698320436 SUCCESS](https://github.com/manufact-test/nomusic/actions/runs/44698320436); [clone ARM13 #44698320481](https://github.com/manufact-test/nomusic/actions/runs/44698320481) pending verification when this text was committed.
- This makes the actual original source-selection sequencing compatible with the existing gate **without changing playback architecture**, but `NativeReplacementLifecycle` remains a pure Java model **not connected to the current clone audio hook**, because semantic ID provenance and decoder pre-prepare are not proven. The current owner Android app remains unchanged.

**Status:** `CELIKOM_REPLACEMENT=NOT_CONNECTED`; `IDENTITY_STATUS=STRUCTURAL_ONLY`. Do not issue NAV46 or claim running audio. Next concrete integration needs publisher-attested exact native Track+Album+edition and live original generation at a demonstrably pre-prepare bound source/decoder decision, then connect verified approved source to the existing original player without a second player.
