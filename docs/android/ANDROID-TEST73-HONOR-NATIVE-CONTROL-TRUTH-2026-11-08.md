## Code audit
* `ProbeService.sample()`: every 250ms calls `MediaController.getCurrentPosition()`, `isPlaying()`, `getPlayWhenReady()` from external Yandex Media3LibraryService; these values construct `PlaybackSource`. Its listener registers `onPositionDiscontinuity`, `onIsPlayingChanged`, `onPlayWhenReadyChanged`; no within-track event is logged on these bad songs during scrubs/pause.
* `ReplacementEngine.update()`: pauses its own decoder when `!s.playing`, detects source seek by `abs(delta over expected playback)>900ms`. When Yandex remote session incorrectly stays playing=true during an actual UI pause, the engine **cannot infer the hidden native UI pause** from these inputs.
* Hot cached seek callbacks typically 38–54ms. Optimizing `MediaPlayer.seekTo`, Range bytes, fade, buffer, album ID or duplicate catalogue is NOT a root-cause fix for the missing UI-to-remote control state.
* Test.73 fixed Quest exact matching and one speculative prefetch budget. **Do not claim** it fixes native source control. Stable Yandex/official Windows works is not evidence of Android external Media3 parity.
