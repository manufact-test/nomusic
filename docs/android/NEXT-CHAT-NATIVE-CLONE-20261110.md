## Чего хочет владелец
**Один APK CELIKOM с настоящей НАТИВНОЙ Яндекс.Музыкой, её оригинальным интерфейсом/входом/плеером/«Моей волной».** Наш модуль заменяет аудио определённых треков из существующего CELIKOM API **в том же штатном плеере**. Пауза, seek, Next, random/«Моя волна» и фон должны работать. Без отдельного плеера, двойного звука, собственного музыкального UI и WebView. Оригинальное приложение Яндекса на телефоне владельца не трогать.

**План согласован окончательно:**
1. Закрытый исследовательский прототип с **LSPatch**, по принципу ChromaSync Clone, **только как временный механизм внедрения**, без распространения клиентам.
2. Довести до настоящего аудио, проверить на тестовом Android с Play Protect ON и зафиксировать точный рабочий эталон.
3. **ОБЯЗАТЕЛЬНО САМОМУ НАПОМНИТЬ владельцу по завершении этапа 2**: «Эталон CELIKOM на LSPatch готов и сохранён. Теперь можем начинать собственный независимый механизм внедрения вместо LSPatch». После его решения — отдельная реализация, замена только механизма, без переписывания CELIKOM.

Восстановленные `android/spike/` и `android/yandex-web-oneclock/` — исторический WebView, не текущая стратегия. **Не переключайся на них и не придумывай Media3.**

## Безопасность и условия
- Максимально привычный вход Яндекса внутри нативного UI; **не читать, не собирать и не отправлять** наши серверы его пароли/cookies/токены; проверять сетевое поведение и код, не принимать отсутствие сохранения пароля за доказательство безопасности.
- CELIKOM авторизуется отдельно, сервер проверяет подписку/3-дневный trial/право на каждую подмену. После окончания доступа звучит только обычный Яндекс.
- Пользователь устанавливает **один APK** с собственным package name/стабильной подписью; обновление запускается из приложения с системным подтверждением.
- Play Protect НЕ отключать. Допустимо обычное предупреждение с кнопкой продолжить; **полная блокировка = STOP, клиентам такой APK не отдаём**. Никаких обходов Play Protect, root, фальшивой подписи Яндекса/Google, перехвата DRM.
- Не менять Windows, Test.50, стабильный Android, production server/DB/catalog, оригинальный Яндекс на основном HONOR. Перед кодом создай отдельную рабочую ветку и backup. Права на распространение модифицированной Яндекс.Музыки и GPL LSPatch требуют отдельной проверки до коммерческого релиза.

## Как начать
Сначала кратко проверь реальное состояние и инвентаризируй наши Android/Windows-наработки и APK конкурента. Затем делай **существенный изолированный технический блок** по нативному in-process source-swap. Не возвращайся с синтетическим «успехом» или старым веб-клиентом: следующий значимый результат — воспроизводимый нативный запуск и путь к реальной подмене одним аудиодвижком. При настоящем блокере покажи доказательства и задай **один конкретный вопрос**, не переизобретая продукт.

**Финальный deliverable первой большой фазы:** проверяемая безопасная тестовая APK с понятным сценарием, commit, SHA256, сохранённая baseline-ветка, реальные проверки; как только владелец примет стабильный вариант на LSPatch — **напомни о начале разработки собственного патча, это обязательство из ТЗ.**
