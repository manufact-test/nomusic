Срок — один ограниченный проход из трёх проверок, не недели исследований. Не делать очередной пассивный модуль или диагностический APK.

## Жёсткий трёхшаговый технический отсев (проход один раз, с финальным VERDICT)

### Gate A — доступный и разрешённый source injection официальной Android Яндекс.Музыки

Проверить только **документированный публичный Android SDK/IPC/plugin/deep link/API** и ранее имеющийся signed DEX census для прямого source rebind / set DataSource перед prepare. Требуется одновременно:
1. Официальный *неизменённый* Yandex APK на обычном Android 13, без root, патча, обхода подписи/Play Protect/DRM;
2. Разрешённое стороннему CELIKOM приложению управление **конкретным аудио DataSource**, не просто pause/seek/queue/MediaSession;
3. Подтверждённый маршрут `current track+edition+generation→same active player→safe source refresh` с пробуемой разрешённой дорожкой.

**Kill**: если API даёт только транспортные команды или требует in-process доступа/привилегий Yandex — `NATIVE_ORIGINAL_NO_GO`. Не строить новый observer. Медиа-контроллер, NotificationListener и MediaProjection не являются source-rebind API.

### Gate B — независимые поддерживаемые пути к официальному контенту внутри CELIKOM

Изучить публичную документацию Яндекса: есть ли **лицензированный, официально разрешённый** SDK/API/web embed с воспроизведением полного каталога/авторизацией на стороннем Android-клиенте. Не использовать неофициальные приватные streaming API, извлечение пользовательских токенов, DRM/key обход, копирование APK/интерфейса Яндекса или их защищённого каталога. Сигнал `CATALOG_AUTHORIZED_GO` возможен только при документированном соглашении и рабочем разрешённом потоке. Иначе `CATALOG_UNAVAILABLE` и не обещать доступ ко всей библиотеке Яндекса.

### Gate C — собственный CELIKOM Android (fallback, если Gate A не прошёл)

Развивать **первостороннее приложение и собственный Android Media3/ExoPlayer**, а не клонированный APK Яндекса, как безопасную основу. Плейлисты, очередь, радио на каталоге, Next/Seek/Pause, фоновое воспроизведение и Bluetooth работают **в одном собственном плеере**. Воспроизводить только:
- подтверждённые правообладателями CELIKOM версии через действующие server entitlement + signed HTTP Range URL;
- личные локальные файлы с согласием владельца (если фича нужна);
- оригинальные дорожки сторонних сервисов ТОЛЬКО при наличии официально документированного и разрешённого SDK/лицензии.

Логин CELIKOM — только серверная верификация подписки/3-дневного trial, `fail-closed` при неподтверждённом entitlement. Не вводить пароль Яндекс.Музыки в CELIKOM; если когда-нибудь появится официальная интеграция, только OAuth в системном браузере и отдельный документированный SDK. Не выдавать «прямо как Яндекс со всей его музыкой» без прав/контентного контракта.

**Acceptance минимального реального продукта:** на отдельно проверенной среде один реальный Media3 player играет разрешённый трек CELIKOM; одни и те же часы управляют паузой, перемоткой, Next и resume; при выключенной подписке нет доступа к альтернативе; Android 13+ background/notification/BT/Play Protect проработаны без обходов; только после этого приватная QA на отдельном устройстве и затем доставка владельцу. Статические тесты или звучание OWN синусоиды ≠ пользовательский PASS.

## Тактический порядок без новых бесконечных спринтов

1. Записать этот документ и поместить ссылку **первой** в `NEXT-CHAT` и навигации. Создать независимую backup-ветку перед изменениями. Никаких других веток трогать.
2. Пройти Gate A по официальным Android API и существующим подтверждённым данным/Windows контракту. Результат **YES с конкретным воспроизводимым методом** либо **NO**; никакого «ещё пара DEX тестов».
3. Пройти Gate B по источникам владельца контента. Записать фактические документы и ограничения, без недоказанной полноты каталога.
4. Если A — NO: **не продолжать native hooklab**. Подготовить/реализовать самостоятельно запускаемый owned-player модуль из существующих first-party частей проекта, с правами и entitlement, в ОТДЕЛЬНОЙ ветке, а не оживлять ненадёжную Test.50.
5. В конце зафиксировать verdict, точные коммиты/CI, бэкапы и переходную точку. К владельцу обращаться только при настоящей задаче для проверки, а не каждые девять минут.

**Никаких изменений:** Windows, расширение, production/API/DB, оригинальный Яндекс/HONOR владельца, Test.50. **Никаких чужих краденых ресурсов, клонирования подписи/пакета, аккаунтных секретов или Play Protect bypass.** Собственный CELIKOM UI допускается со знакомым пользовательским сценарием, но без копирования охраняемых чужих экранов или кода.
