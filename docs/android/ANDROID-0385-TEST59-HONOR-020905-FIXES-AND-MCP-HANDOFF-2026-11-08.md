# CELIKOM Android Test.59 — исправлены доказанные регрессии и сохранено для переноса MCP
**Дата:** 2026-11-08. **Статус:** подписанная тестовая APK готова, CI PASS, работа на реальном HONOR 50 ещё не проверена. Не выдавать телефонную приёмку за подтверждённый fix.

## Что сказал владелец
Test.58 отклонена на HONOR 50: RASKOL и «Дым» всё ещё неуправляемы; при переходе к «Дыму» Яндекс пишет потерю связи; ранее стабильная песня в начале видео перестала подменяться; ещё несколько песен могут не заменяться. Владелец требует **НОВУЮ** версию от принятой Test.50, а не очередной откат/декоративную правку. После этой работы планируется окончательная миграция с Hostinger и работа через MCP, поэтому сохранять все исходники и результаты.

## Привязка только к последнему журналу
- **Полевые исходники:** `CELIKOM-combined-20261108-020905.txt` (3 сегмента: Test.55, Test.57, **последний Test.58**) и `SVID_20261108_020713_1.mp4` (105.26с). **Анализировать последний сегмент** Test.58 с `run_start 2026-11-08T02:06:56+03:00`, длительность 128.64с. Не смешивать предыдущие сегменты.
- Среда: HONOR NTH-NX9, Android 13, **Яндекс Музыка 2026.10.3 #170gpr** (обновилась относительно ранних логов 2026.09.5); VPN=true, Wi-Fi=true, preflight/resolve backend HTTP200.
- **Явный дефект №1 — потеря соединения на «Дым»:** album `5281614`, trackId `39949113`, Yandex alias `363`. ~101.99с Media3 подключён и видит правильную песню, `STATE_BUFFERING=2/playWhenReady=true/isPlaying=false`; собственная версия backend найдена (`replacement_resolve found=true`) и декодер приготовлен. ~105.17с срабатывает `source_controller_refresh reason=quiet_buffering_snapshot`. **В принятой Test.50 и диагностической Test.58 это вызывает** `controller=null; replacement.update(null); c.release(); connect()` хотя контроллер не был отключён. С ~105.22с далее соединения получают `ExecutionException causeType=SecurityException` (7 повторных отказов до конца записи); после этого CELIKOM сообщает «Потеряна связь». Это наша доказанная регрессия. **Исправление:** не освобождать подключённый контроллер из-за длительной буферизации: `source_controller_buffering_retained`, при этом оставить оригинал доступным/не запускать замену без штатного READY. Отдельный `onDisconnected` и случаи реальной потери источника по-прежнему обрабатываются эталонными механизмами.
- **Явный дефект №2 — ранее стабильная «Мне нужна любовь» (Татем):** в 21.59с и снова 36.40с Yandex alias `227`, album `28055398`, duration `102380ms`. Yandex открытый API для альбома вернул **HTTP 451 REGION_RESTRICTION** в 15.88с; `hybrid_identity` присвоил `decision=no_unique_candidate` из-за того, что подписанный Test.58 содержал собственный каталог **всего 12 строк**, `ownCatalogue=STALE_OR_INCOMPLETE_SNAPSHOT`, `learnedCatalogue=NO_MATCH`. Это НЕ ошибка аудиофайла или отсутствие одобренной версии.
- **Проверка по реальному источнику:** подписанная Test.52 APK уже имела **119 проверенных approved-песен**, включая `trackId 118910020`, `title=Мне нужна любовь`, `artist=Татем`, `duration_ms=102380`. Во время build Test.59 выполнен **новый read-only SQL SELECT из живой БД Hostinger** с `complete=true`, 119/119, timestamp `2026-11-07T23:19:18.396Z`, и строка `118910020` лично подтверждена **в готовой подписанной APK**. Не использована копия со старым timestamp, никто не переписывал БД и не добавлял исключений по названию в рабочую логику.
- **Pause/Seek RASKOL**: alias `254`, trackId `42884423`. В Test.58 `media3_remote_event_evidence` показывает `playWhenReady=true/isPlaying=true`; для RASKOL заметны изменения рассчитанного курсора на 80.97/84.04/91.44с без ожидаемых `SAME_ITEM_SEEK`, и собственный `replacement_hot_cached_seek_ack` занимает ~50–60мс после получения target. Для хорошей «Легко ли быть молодым» у Media3 есть нормальный `SAME_ITEM_SEEK` на ~35.17с. **Реальная причина отсутствия UI Pause/Seek у Яндекса по-прежнему не доказана**. Внешний `MediaController.getCurrentPosition()` может интерполировать позицию локально; нельзя выдавать её движение за подтверждение работы Yandex PCM.
- **Подключение при запуске:** в Test.58 ещё до первого подключённого Media3 были несколько начальных `SecurityException` (~0–10с); подключился с 6-й попытки через ~15.3с. Test.59 **не изменяет этот режим** и не обещает, что быстрый запуск всех песен починен. Не чинить догадками через второй контроллер (Test.52 rejected) или Accessibility/Notification Listener (владелец не принимает).
- Read-only диагностика Test.58 установила единственный публично объявленный Media3LibraryService Яндекса (по текущей package visibility); альтернативного подтверждённого управляющего сервиса пока нет. В Test.59 не сохранять новые тяжёлые логи Test.58, чтобы вернуть обычное поведение эталона.
