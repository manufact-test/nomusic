### Проверены и отклонены как неподходящие

- [BandLink Partner API](https://yandex.com/support/music-artists/ru/performers-and-copyright-holders/partners-api) позволяет создавать/обновлять **смартлинки**, а не управлять источником нативного плеера Яндекса. Не использовать Bearer-токены BandLink для этой задачи.
- [Яндекс API Партнёрского интерфейса](https://yandex.ru/dev/partner/) — рекламные и коммерческие инструменты, не Яндекс Музыка Android source extension.
- [Публикация музыки через дистрибьюторов](https://yandex.ru/support/music/ru/performers-and-copyright-holders/terms) — легальный альтернативный продуктовый путь; он НЕ осуществляет перехват текущего аудио и НЕ является готовым CELIKOM Android.

## Технический annex — предоставлять только по запросу команды Яндекса

**Нужно:** официальное разрешённое расширение оригинального Android-плеера Яндекса, в котором подписанный издателем хост предоставляет:

- авторитетную идентичность активного трека (catalogue trackId + конкретное издание/версия + playback generation), без чтения токенов, приватных запросов и библиотеки пользователя;
- вход для авторизованного и подтверждённого правообладателями внешнего source descriptor **до подготовки собственных media source / decoder**, с возможностью отказа/фолбэка на штатный источник;
- одну медиа-сессию и один нативный проигрыватель Яндекса на протяжении playback, seek/pause/Next/radio;
- контроль codec, длительности, HTTP Range, криптографии/DRM и прав без перехвата защищённых потоков и без обхода защиты клиента;
- тестовую среду/техническую документацию для интеграции без переподписывания чужого APK, несанкционированной инструментации, root и отключения Play Protect.

**Критично:** сторонний Android `MediaController` не является доказательством audio-source API. В изолированном CI на неподменённом подписанном Яндексе [42785272172](https://github.com/manufact-test/nomusic/actions/runs/42785272172) публичный binder не предоставил соединение — `PUBLIC_BIND_REJECTED`, даже после запуска оригинального UI без входа. Это наша внутренняя диагностическая информация, **не включать в первое обращение**. Не прикладывать дампы APK/DEX, токены, музыку, ключи, логи или исходный код.

## Следующее действие и честный gate

- Владелец выбирает корпоративную подпись и отправляет первое сообщение через официальный канал; **ни одно обращение не отправлено из этого репозитория/чата**.
- До ответа не делать новых попыток репакета, root/x86 LSPatch, случайных DEX-патчей и тестов замены звука.
- Положительный ответ проверять строго: письменное разрешение + документация поддерживаемой Android native source точki + право на этот конкретный сценарий + тестовый подписанный хост. Просто «есть API» или «можно добавлять музыку в каталог» = **НЕ GO**.
- Если ответ «такая интеграция не поддерживается», зафиксировать **NO-GO по данным от правообладателя платформы** и не обещать Android-подмену в оригинальном Яндексе.
- Test.50, HONOR, Windows, расширение, БД, сервер и production не трогать.
