## Why — grounded in pinned upstream LSPatch v1.2
Exact source inspected: https://github.com/JingMatrix/LSPatch/blob/v1.2/patch-loader/src/main/java/org/lsposed/lspatch/loader/LSPApplication.java . `createLoadedApkWithContext()` extracts the preserved `assets/lspatch/origin.apk` into the app's private cache and sets both `ApplicationInfo.sourceDir` and `ApplicationInfo.publicSourceDir` to that cached APK **before creating the target `LoadedApk`**. This makes the cached *inner* original APK the expected runtime code/resource source, irrespective of editing the surrounding *outer* APK resource table. This is an upstream source observation and consistent with runtime Firebase lookup; the actual `LoadedApk.mResDir` value in CELIKOM has not yet been directly classified.
