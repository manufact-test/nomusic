# Android A1 — реальная причинная проверка загруженного ChromaSync, 12 ноября 2026

**Ниже — настоящий ARM64+ARMv7 Android 13, а не синтетика. Продукт пока Stage A NO-GO / Stage B LOCKED.**

## Что точно делает конкурент

Ранее проверенный целый ChromaSync 3.0.1 из **уже загруженного владельцем** приватного draft APK (SHA256 `4e6edb1c471f6b3715eae4c0a35f0bd898b0daaa87f3f8fb3ba0b20d1638b53d`) содержит 2025.10.4 нативный Яндекс в `assets/lspatch/origin.apk`, собственный модуль `app.mywave.injector` и upstream LSPatch с `sigBypassLevel=2`. Предыдущее исследование подтвердило: **полный ChromaSync живёт 75 с / 25 из 25**, а его побайтно извлечённый origin **без оболочки падает**. Декодер находится внутри Яндекса; внешний «декодер» не нужен. Приложение конкурента не доказывает нам свой авторизованный звук и не предоставляет прав на его исходники.

## Реальные дифференциальные проверки сегодня

1. **Готовая оригинальная RuStore/GPR 2026 серия в раннем эксперименте:** upstream archive уже не совпал с закреплённым SHA, остановили до запуска; никаких выводов про LSPatch2 на 2026 из этого нет. CI [43185479247](https://github.com/manufact-test/nomusic/actions/runs/43185479247). Не повторять изменившуюся загрузку.
2. **Загруженные 16 issuer-signed 2025.10.4 GPR XAPK:** исходные байты/подписи криптографически подтверждены; 16 собственных независимых подписанных split-APK корректно созданы, LSPatch v1.2-487 уровня **2** завернул собственный base; исправлена известная upstream ошибка CRC вложенного APK и выполнена проверка получившейся подписи. Android13 `PackageManager` установил **все 16**, MAIN Activity стартовала, но упала **JAVA_CRASH / ILLEGAL_STATE / SIGNATURE**. Это не живой нативный CELIKOM. [Настоящий CI 43187101757](https://github.com/manufact-test/nomusic/actions/runs/43187101757).
3. **Ровно тот же вложенный host из целого успешного ChromaSync:** отдельно собрана собственная подпись/оболочка на **проверенном неизменном nested-origin** с upstream LSPatch `sigBypassLevel=2`, **без модуля**. Код/ключи/модуль конкурента не использованы, CRC исправлен с последующей собственной подписью. Установилось, MAIN принята, но **JAVA_CRASH**: 8/25 samples alive, 4/25 resumed. [Реальный CI 43187056087](https://github.com/manufact-test/nomusic/actions/runs/43187056087). Значит, **один только уровень 2 не воспроизводит успешный целый APK**.
4. **С тем же самым host + той же собственной LSPatch2 оболочкой, но с ОДНИМ собственным ИНЕРТНЫМ LibXposed модулем** (никаких hooks, permissions, данных, чужого кода; exact package scope): Gradle собрал модуль, подписал собственной debug подписью, 1 модуль штатно встроился. Android13 установка и MAIN приняты; исход **такой же JAVA_CRASH**, 8/25 alive, 4/25 resumed. [CI 43187978844](https://github.com/manufact-test/nomusic/actions/runs/43187978844). Просто присутствие модуля проблему тоже не решает.

Все прогоны выполнялись в изолированном disposable Android13 CI: исходные vendor APK и competitor outer неизменны, пользовательский HONOR/Test.50/Windows/backend/production не затронуты; никакие чужие APK/сессионные данные/ключи не опубликованы, после прогона гостевая среда и промежуточные файлы уничтожались.

## Точный вывод для следующего ведущего разработчика

**Перестать предлагать поиск декодера, WebView, второй плеер и продолжение изолированных PHP contract tests.** Настоящий путь конкурента: native Yandex inside LSPatch shell + **непустая собственная логика инжектора**. Но проверить, какая именно комбинация собственного кода инжектора, версия загрузчика, подпись/ресурсная упаковка, настройка и окружение обеспечивают его boot, **пока не удалось**. Нельзя утверждать, что виноват именно его инжектор: одновременно различаются собственная упаковка/сертификат. Три самостоятельные честно подписанные LSPatch2 комбинации **не дают живую MAIN**. Никакого пользовательского APK, работающего native source-before-prepare, авторизации/звука нет. Main issue #41 открыт; Stage A NO-GO / Stage B LOCKED.

**Изолированная ветка:** `experiment/android-a1-competitor-loader-level2-causal-20261112`. Для продолжения нужны новые **доказательные** изменения native startup, а не повтор прежних трёх без изменений. Собственная main A1 `experiment/android-native-a1-lspatch-clone-loader0-20261111` @ `cc4cb0f93489168db21502f3ef195855ae9fb743` не тронута. Разделить Android-app boot (не проходит), аудио (даже не запускается), и CI (фактические негативные результаты).

Изолированные подписи/оболочки на уровне 2 — только проверка архитектуры конкурента в ephemeral CI, **не одобрение** внедрения механизмов обхода доверия в пользовательский продукт.
