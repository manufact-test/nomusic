# CELIKOM Android — контрольная точка 0.3.92; дальнейшая работа только в Test (06.11.2026)

## Решение владельца и фактический итог

- **Основная Android `0.3.92` / `versionCode 93` установлена владельцем на HONOR 50 (Android 13); владелец подтвердил «Я установил, все ок».** Скриншот Google Play Защиты перед установкой: «Судя по всему, приложение безопасное», доступна кнопка «Установить». Прежняя категорическая блокировка «Вредоносное приложение заблокировано» **на этой проверке не воспроизвелась**.
- Это **полевое подтверждение одной установки**, а не доказательство, что Play Protect не покажет предупреждения другим пользователям, на других устройствах или в будущих APK. Не писать «Google гарантированно одобряет CELIKOM».
- В пользовательском скриншоте за окном установки показано **0.3.90**: окно возникло до завершения обновления. Результат установки 0.3.92 подтверждён отдельным следующим сообщением владельца.
- **Владелец поручил документально сохранить точку и дальше исправлять нюансы только в отдельном Android Test.** Stable `0.3.92` / `pro.celikom.nativeprobe`, текущий серверный OTA-манифест, ПК-расширение, backend и веб-сайт **заморозить** до отдельного прямого разрешения. Не переносить Test в stable автоматически.

## Изменение в 0.3.92 и важная граница проверки

- Код Android UpdateCenter теперь **скачивает APK через системный `DownloadManager`**, проверяет SHA-256, размер, package, version и оригинальный сертификат. После загрузки пользователь открывает уведомление/«Загрузки Android» для системной установки. Убраны app-owned installer flow, `REQUEST_INSTALL_PACKAGES` и локальные installer/provider-компоненты.
- Исправление в `verify_release.py` после первого неуспешного публикационного прогона различает разрешённый `DownloadManager.ACTION_VIEW_DOWNLOADS` и запрет на прямой `Intent.ACTION_VIEW` / `ACTION_INSTALL_PACKAGE`. Это **ошибка теста**, не Android audio. Повторный #42258067172 успешно собрал, подписал и опубликовал APK.
- **Новый механизм `DownloadManager` ещё не проходил полный цикл следующего обновления на устройстве.** Скриншот успешной установки 0.3.92 сделан поверх установленной 0.3.90, где инициатором обновления был прежний код. Не приписывать отсутствие блокировки доказанной эффективности `DownloadManager`; при следующем согласованном production-релизе отдельно проверить этот путь.
- Android Audio/Test.47 перенесена в основной APK ранее, но **качество звуковых стыков не объявлено окончательно принятым**. Версия stable сохранена как функционирующая база; доработки звучания — строго в тестовом пакете.

## Отдельное Test-приложение — дальнейший маршрут

1. Работать с Android **`pro.celikom.nativeprobe.test`** (отдельный package ID, separate signing/package/OTA contracts), начиная с последнего подтверждённого тестового аудиокода **Test.47 / `0.3.85-test.47` / code `86132`**; baseline source `9c90a73fc87a0b9b12d6c4da66c98028b14073cc` в `backup/android-0385-test47-owner-selected-20261106`. Test.33 остаётся старым golden rollback; Test.46 — сравнение. **Не пересобирать stable 0.3.92 ради испытаний.**
2. Следующий тестовый номер — после сверки существующих веток и release metadata, **не создавать конфликтующий code/versionName**. Исправления собирать крупным логичным пакетом, не выпускать APK после каждой мелочи. Явно проверять, что CI Test сохраняет original signer, `pro.celikom.nativeprobe.test`, `stable_published=false`, `stable_ota_touched=false`, `hostinger_write_performed=false`.
3. Открытые проблемы звука: слышимые «пшики»/скачки уровня при подмене, нестабильные поздние подключения к следующему треку (в том числе после Next), иногда заметные паузы при seek, деградация после длительного прослушивания/серии переходов, возможные редкие возвраты к оригиналу. Сопоставлять combined diagnostics с ощущениями владельца; отдельные transport ms **не доказывают акустический дефект или успех**.
4. Уже рассмотренный Test.47 устранил ложное ожидание 1200ms при promoted in-flight speculation, приоритизировал текущий трек, расширил лимит файлов кэша 12→16 при неизменных 96MiB. Однако владелец не заметил существенной разницы Test.47 vs Test.46; **не повторять эти изменения без нового доказанного случая**. Источник: [Test.47 session stability](ANDROID-0385-TEST47-SESSION-STABILITY-2026-11-06.md).
5. Отклонённые эксперименты (включая strict Test.40) не восстанавливать автоматически. Перед новой аудио-архитектурой сверить эволюцию Test.33 → Test.47, контракт Yandex smooth transition и сохранение оригинального звука до verified replacement. Отдельный backend-каталог с `found:false` не чинить изменениями desktop/API в рамках этой Android задачи.
6. Тестировать на HONOR только следующий **изолированный Test APK**, одним полевым проходом: начало песен, ручной Next, естественная смена трека, повтор уже прогретого, seek и длинная shuffle-сессия; затем собрать один combined journal и короткую оценку слышимости. Для ПК ничего не меняется.
