## What this proves and what it does not

1. **Different failure sites.** An uncached HTTP Range fetch can take seconds. Separately, even fast verified decoder seeks currently force Yandex-original/unmute then replacement/remute, creating an unnecessary audible transfer. Separately again, UI pause can be invisible to CELIKOM's source session. Solving only one does not solve all three.
2. **Transport ≠ audio.** `MediaPlayer.getTimestamp()` describes the replacement output clock; it does not measure the PCM, phase, loudness or speaker presentation of Yandex's original. No verified zero-click crossfade can be guaranteed between independent players purely from two transport positions.
3. **No permission-free observation guarantee.** The standard Media3 `Player` state and pause indicators are documented as session-published values. If the upstream session remains playing while its application UI is paused, CELIKOM cannot deduce the missing action from that same data. Android `MediaSessionManager.getActiveSessions` requires privileged media-control permission or explicitly enabled Notification Listener access; such a redesign adds privacy, user-consent, availability and marketplace implications and still requires proving that a *different* Yandex session exposes the missing pause. Do not enable intrusive access on this evidence alone. References: [Android Player state](https://developer.android.com/media/media3/session/player), [Android MediaSessionManager](https://developer.android.com/reference/android/media/session/MediaSessionManager).
4. **No fake guarantees.** There is no engineering basis to promise perfect random uncached seeks over variable CDN/VPN, perfectly phase-continuous overlay handover, and Yandex UI pause reflection solely by retuning intervals. This is an **integration architecture limit**, not proof that the owner pressed incorrectly or a problem with the audio file.
