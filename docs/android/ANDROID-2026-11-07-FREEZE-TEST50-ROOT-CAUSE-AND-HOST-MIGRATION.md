## 3. Что удалось установить из реальных логов / видео
**Источник:** combined выше, в нём три запуска: Test.51 (769 событий), Test.52 (1202), Test.53 (921). Последний Test.53 начат 2026-11-07 15:24:19 +03:00; не путать с предыдущими сегментами.
1. **RASKOL «Нас не понимают вообще»** — album `5685525`, candidate track `42884423`. Пользователь наблюдает неработающую Pause и запаздывающую Seek. В прошлых логах ответы *нашего* декодера на опубликованную перемотку занимали десятки миллисекунд, поэтому задержку от нажатия в Яндексе нельзя приписывать только декодеру. Native Media3 binder может показывать `isPlaying=true`, когда UI Яндекса выглядит остановленным. Физическая причина разницы официального UI и Media3 не доказана.
2. **Лёша Свик «Дым»** — album `5281614`, track `39949113`. В Test.53 на переходе с RASKOL около 80.85с идентичность `UNIQUE_CANDIDATE` успешно определена; у Яндекса `playWhenReady=true`, но `playbackState=BUFFERING (2)`, `isPlaying=false` и позиция 0. В 84.00с `source_controller_snapshot_probe` подтверждает затянувшееся buffering. **Это не команда Pause и не провал определения песни.** Позднее после «тело» тот же «Дым» снова определяется. Разный результат в зависимости от истории переключений — ключевой указатель на проблему последовательности/состояния Yandex Media3, а не на недостаток MP3 как доказанный факт.
3. **Ошибочная подмена / старая песня продолжает играть**: при переходе «Дым» → «Хлоп-Хлоп» → назад пользователь ранее видел несовпадение выбранной песни и звука; Media3 может отставать от фактической смены в официальном приложении. Test.53 пыталась предотвращать это, но ложные срабатывания навредили обычным песням. Не переносить этот алгоритм.
4. **Test.53 регресс на нормальной «ты»** — в 46.22с произошёл `source_audio_quarantine_started`, `oldAlias=250`, `media3EventAgeMs=3566`, `audioActivityAgeMs=88`, `activeMediaPlayers=1`. Спустя ~0.19с нормальная смена источника на «Легко ли быть молодым» уже обрабатывалась. Само событие открытия аудиосессии + один активный плеер **не доказывает смену или остановку именно целевого трека**. Это ошибочное условие блокировки.
5. **Проблемы определения — отдельная категория:** HTTP `451 REGION_RESTRICTION` из открытого API альбомов Яндекса. В Test.53, например, `Биг сити лайф` получила 451 для album `482139`, но затем смогла идентифицироваться через собственный свежий каталог (`OWN_CATALOGUE_METADATA`, ID `40371622`). «Он рядом» (Quest Pistols / Quest Pistols Show) получала `no_unique_candidate`. Нельзя путать отказ API с обрывом соединения Media3 или с отсутствием самой загруженной версии.
6. **Каталог Test.52/53:** 119 доступных approved-подмен в свежем read-only snapshot. Само расширение каталога и `451` не дают права обходить строгую проверку уникальности альбомной версии, иначе можно поставить не ту песню.
7. На обычных песнях переходы и замену необходимо сохранить как в Test.50. Все три проблемы — **управление Pause/Seek**, **статус перехода/застревание buffering** и **региональная/неоднозначная идентификация** — анализировать отдельно.
