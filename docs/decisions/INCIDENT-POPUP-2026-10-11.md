# CELIKOM 0.4.24 — явный экран при объявленном сбое

Владелец попросил заменить обычные кнопки красной рамкой с понятным сообщением. Ранее клиент показывал только короткие статусы; это не считалось достаточным UX для массовой поломки интеграции.

Клиент 0.4.24: вместо управления музыкой, загрузки и предложения песни — красный блок:

**Подмена временно приостановлена**

Интеграция с Яндекс Музыкой временно недоступна. Мы восстанавливаем её работу.

Время действующего доступа заморожено. Оригинальная музыка доступна.

Аккаунт остаётся доступен. Технический блок и строки трека/версии/доступа скрываются вместе с музыкальными действиями, чтобы не выдавать противоречивые подсказки. После подтверждённого завершения incident обычный интерфейс возвращается автоматически. Desired enabled / ручные Stop и Original не меняются.

Состояние берётся из публичного /api/v1/config независимо от аккаунта, trial, наличия вкладки Yandex и работоспособности адаптера; обновление каждые 5 секунд при открытом popup. Кэш только для отображения сразу при повторном открытии. Network error не объявляет incident и не снимает последний подтверждённый. Валидный active=false снимает старый suspended-флаг остановленного content script, чтобы не заблокировать Start навсегда. Этот UX-кэш не авторизует playback и не активирует trial. Авторитет доступа остаётся на backend.

Сервер остаётся 0.4.23-df8bd247b9ae0a6ff1ecc75f453403fa84be8529: новых миграций, deploy или объявленных live сбоев нет. Реальные платежи/списания не подключены; сообщение относится к времени действующего доступа, не к заморозке денег.

Проверки: anonymous/stopped/no-tab; активный сбой и его завершение; сохранение последнего подтверждённого при network failure; malformed/other service не объявляет сбой; reopening cache; native Chromium реальный красный border, исчезновение музыкальных кнопок, доступный аккаунт и автоматический возврат без клика Start. Владелец не должен объявлять реальный outage ради проверки UI.

Полный клиент, не отдельный UI patch. PR #6 OPEN/unmerged, Issue #7 OPEN. Первопричина исходного Yandex stall не доказана; 11/12 и коммерческие зависимости 13 остаются частичными.
