# Owner promo access — 11.10.2026

Owner decisions: a 100% code adds its configured days to existing remaining access (7 + 30 = 37). Owner may choose lifetime instead of days, only at 100%, with a separate explicit confirmation before creation. Every account can activate a given code once; owner configures its global cap (default 1). Lifetime access is revocable.

Admin section «Промокоды»: create code/title, discount percentage, configurable day duration or lifetime, global cap, explicitly selected activation deadline policy. «Активации» lists account, code, activation time, duration and effective deadline or lifetime. Each activation can be revoked separately. Closing a code prevents future activations while preserving issued access. Individual revocation keeps the one-use record, immutable entitlement grant, usage count and audit. Later separately issued codes retain their own days; revoked days cannot be carried forward by stacking.

100% grants use shared EntitlementService, including audio Range enforcement and incident suspension/freeze. Promo access does not create payment, paid referral, reward credit or subscription. An active promo does not consume an unused trial. Lesser percentages are saved but cannot be redeemed before payment integration; no free-time substitute is used. Short-window monthly price calculation remains a payment-dependent decision.

Additive migration 015 creates promo codes, redemptions and hashed attempt counters; no applied migration is edited and no existing policy, ledger, allocation or access is reset. Account/code locks and unique (code,account) protect concurrency and retries. Owner mutations require role and CSRF. Redeem requires a verified active account and bearer session; HMAC account/device/IP quotas limit attempts in 15-minute windows. Raw codes are excluded from audit payloads.

Implementation verification and deployment are in progress. No real codes or grants have been issued by this work. Latest accepted installed client remains 0.4.25.
