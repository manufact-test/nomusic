# CELIKOM 0.4.53 — upload HTTP 415 + popup stability incident (2026-10-18)

## Incident evidence
Owner submitted a file labeled MP3 for Yandex track `48591846` (Каменные цветы).
Client diagnostics: upload attempt `211f7bd8-2473-4430-9d4d-7c8def344875`,
11,118,847 source bytes, transport progressed to 100% in about 1.1 seconds,
then server replied HTTP 415 `invalid_mp3`.
Therefore the cause of this attempt was *server-side format rejection after
transfer*, NOT popup closure, a stuck 0% connection or transport timeout.
The precise invalid subcondition for this particular audio cannot be
proven without inspecting the actual user MP3 bytes.

### Findings in the previous implementation
1. The server chained finfo's platform-specific `audio/mpeg` MIME guess
   with strict MPEG-III frame validation, causing false negatives for some
   valid tagged files.
2. The client and server accepted only ID3v1 plus small zero padding;
   bounded ordinary APEv2 trailers were not recognized.
3. Uninspectable local audio produced a warning saying the server would
   check it; the Submit button remained enabled. This caused wasted uploads
   and seemingly contradictory error messages.
4. Popup code called `scrollIntoView` during duration checks and hid the
   entire form as soon as the background upload was detected.
   Progress/cancel/feedback also entered the layout without a reserved slot.

## Repairs
- Server uses the bounded strict MP3 frame parser directly; finfo guesses
  cannot reject an otherwise structurally valid MPEG Layer III file.
- The server and client recognize bounded APEv2 and ID3v1 trailing metadata
  (version, byte size and item count validated, no arbitrary payload allowed).
  Malformed frames and nonzero unrecognized tails remain rejected.
- The client treats an unmeasurable MP3/M4A as blocking and describes
  what to do; it does not POST a file it cannot inspect.
- Popup never requests scrolling during selection/submission; the form
  remains rendered while the offscreen worker uploads; status, progress and
  cancel share a fixed-height location.
- Background transfer, idempotency, local journal, rights declaration and
  Track ID pinning remain in place; no extra browser tab.
- Tests include realistic synthetic full-duration MPEG frames in popup
  integration tests, tagged MP3 approval staging in isolated MySQL and
  damaged metadata rejection. No copyrighted audio is included in fixtures.

## Release gates / limitations
Run `npm run ci` in isolated MySQL, verify PHP syntax, manifest, Chrome ZIP
and regression tests before deployment to Hostinger. On Hostinger, use only
the guarded deploy process with snapshot, on-host PHP/DB health and recovery
audit. Never modify approved audio, replace current mappings, or merge PR #6.
Owner's exact download was NOT attached in this chat, so its validity and
eventual acceptance cannot be independently guaranteed. If the same source
still fails after deployment, obtain the file and reproduce inspector failure
locally; do not disable content checks merely to make an upload succeed.
