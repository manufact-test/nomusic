## Что было и что сделано
В 0.4.73 только тип «Проблема с песней» прикладывал ограниченный технический отчёт. Обычное сообщение отправлялось одним текстом.

Теперь обычное обращение получает автоматический снимок: версия, состояние связи и плеера, текущая песня при уверенном определении, позиция/пауза, коды ошибок, недавние сетевые ответы и ограниченная история подключений. Не требуются ручное копирование и административная кнопка.

Снимок создаётся при отправке. Неоднозначный ответ сети не приводит к новому снимку или второму обращению: тот же request key и вложение сохраняются в черновике для точного повтора. Если сбор состояния не удался, текст всё равно можно отправить с минимальным отчётом о недоступности снимка.

В админке: **Техподдержка → обращение → Скачать диагностику JSON**. Обычная переписка, уведомления и ответ пользователю сохранены. Прежние обращения без вложения не изменяются.

## Защита и совместимость
- Сбор ограничен белым списком. Не включаются токены, пароли, аккаунт, HTTP-заголовки, подписанные аудиоссылки, произвольные логи или исходники.
- На сервере данные очищаются повторно. Общий JSON ограничен; клиент оставляет запас под максимальный текст сообщения.
- Обычный пользователь не получает административный экспорт. Общие вложения также исключаются из клиентского чтения переписки.
- Административное скачивание требует текущую сессию owner/moderator. Анонимный запрос и viewer запрещены.
- Обычный запрос использует отдельное поле `support_diagnostics`. Старые сообщения без вложения, song reports и ранее игнорировавшиеся поля других клиентов совместимы.
- Сохранён контракт Windows W70 из `3c01da7e9edd4acd2e4f74f3a43801b081c49f1d`: необязательный пятый аргумент diagnostics, WindowsSupportDiagnostics, скачивание и приватность. Его исходные серверные сценарии включены в общие тесты.
- Код Android и Windows-приложения не менялся.
- Алгоритмы подмены, загрузки аудио, синхронизации и переключения остались принятыми 0.4.73. В player/core.ts изменён только номер версии.
