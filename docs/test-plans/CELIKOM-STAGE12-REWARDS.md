> **11.10.2026 — второй пакет, правила и решения по наградам.**
> Миграция 012, RewardPolicyService/RewardDecisionService и owner-only раздел админки.
> Политика по умолчанию выключена, процент/лимит/срок не назначены. Владелец задаёт
> процент одного бонуса, MAX_DISCOUNT_PERCENT (предел суммы бонусов),
> MAX_REWARD_PER_MONTH (число начислений одному аккаунту за календарный месяц UTC)
> и срок действия в днях. Это отдельный лимит количества; для будущей денежной
> модели при необходимости добавить бюджет в валюте, не смешивая его с процентом.
> Каждый grant хранит процент, срок, ревизию политики и администратора. Старые
> начисления не пересчитываются при изменении политики. Общий предел ограничивает
> потенциальную сумму скидок, все grants учитываются в лимите месяца даже после
> отмены или истечения. Ручные approve/reject/revoke/expire — только владелец + CSRF,
> причина и optimistic revision; изменения и аудит атомарны. При начислении повторно
> проверяются активная версия и подтверждённый аккаунт. Истёкший/отменённый/недоступный
> бонус исключается из расчёта без cron. Клиент не может начислить/потратить бонус.
> reward_available/discount_active/application_available остаются false: это ещё
> не применённая скидка и не доступ. GET сообщает approved_credits и ограниченный
> potential_discount_percent. Отдельное использование с конкретным billing event,
> защита повторного списания и комбинирование с referral/promo — после платежей #12.
> Одобрение версии не начисляет процент автоматически: оно создаёт pending-вклад;
> владелец принимает отдельное решение в разделе «Награды за вклад».
> Полный прогон и безопасный rollout выполняются до ручной проверки. Ранние строки

# Этап 12: доказательство одобренного вклада, первый серверный пакет

Дата: 11.10.2026. Ветка `feature/api-range`, подготовка 0.4.16.
Issue: https://github.com/manufact-test/nomusic/issues/13 .
Требования: Master ТЗ MVP v1.5, §17.1–17.3 (стр. 18), План MVP v1.6,
этап 12 (стр. 31–32). По решению владельца платежи пока отложены в #12.

## Граница реализации

`reward_ledger` хранит доказательство вклада со статусом `pending` после настоящего
moderation approve. Это ожидание решения по политике наград, а не награда,
выданная скидка, бонусное время или основание EntitlementService.
Размер награды по §17.2 не определён; в этом пакете нет выдуманной суммы,
процента, срока или условий накопления. Состояния approved/rejected/used/expired
заложены в схеме, но переходов в них пока нет.

`FEATURE_REWARD_ELIGIBILITY=0` по умолчанию, требуется миграция 011.
Пакет не развёрнут на Hostinger. Существующие trials/сессии/версии песен,
приватное аудио и владельческие credentials не меняются. Нет backfill:
ранние загрузки с неизвестным автором не присваиваются текущему аккаунту.
Рабочую установленную 0.4.4 сохранять. PR #6 не сливать, Issue #7 не закрывать.

## Связь с настоящей загрузкой и модерацией

При создании новой пользовательской версии `uploaded_by_user_id` записывается
из проверенной bearer-сессии. Поля multipart `user_id`/`uploaded_by_user_id`
не определяют автора. Owner-only upload оставляет NULL. Повтор запроса и
переиспользование кандидата сохраняют первого автора.

ModerationService вызывает RewardService только при `approve` pending-кандидата
и только при включённом флаге. Проверяются фактическое одобрение, активность,
администратор решения, наличие подтверждённого активного аккаунта автора.
Запись вклада, запись аудита, изменение каталога и аудит модерации фиксируются
в одной транзакции. Любая ошибка откатывает все изменения.

Один физический AudioAsset может дать только одну запись. Право первичного
учёта имеет автор первой связи этого файла. Повторный upload, новое имя файла,
вторая связь с другим Track ID, другой пользователь и disable/reactivate не
создают нового вклада. Если первая связь была отклонена или является старым
owner-only seed, последующая привязка тех же байтов не считается новым вкладом.
Это консервативная защита exact duplicates; acoustic fingerprint qualification
в этот пакет не входит.

Смена/отключение одобренной версии не стирает историческое доказательство.
Перед будущим начислением необходимо повторно проверить актуальную пригодность
версии и аккаунта; наличие pending-записи само по себе не разрешает выплату.

Блокировка AudioAsset сериализует повторы по разным Track ID. Проверка уже
созданной записи использует current read с FOR UPDATE, чтобы при MySQL
REPEATABLE READ не переиспользовать snapshot до фиксации другого обработчика.
Уникальные ограничения обеспечивают один asset и один replacement на запись.

## API

`GET /api/v1/rewards` default-off, требует действующую сессию, отдаёт только
собственный pending_contributions и явно false для reward_available,
discount_active, policy_configured. `user_id` в query не меняет владельца.
Нет чужих email/ID, аудиоссылок или storage keys. Cache-Control: no-store.
POST и клиентские утверждения approved/discount не начисляют ничего.
После выхода/revoke API возвращает 401.

## Автоматическая проверка

`server/tests/rewards.php`, только одноразовая `celikom_test*` MySQL:

- Настоящий UploadService: автор из доверенного параметра, multipart spoof
  игнорируется; retry не меняет автора; pending не создаёт reward/access.
- Approve создаёт одну pending-запись и один audit, другой аккаунт не получает её.
- Повторы, disable/reactivate, другой Track ID с тем же AudioAsset не удваивают её.
- Reject/duplicate/wrong_track/bad_quality и owner-only seed не награждаются.
- Ошибка аудита модерации через изолированный test trigger откатывает каталог,
  reward_ledger и reward audit; trigger удаляется в finally.
- API: выключенный gate, bearer, собственный агрегат, no-store, запрет grant POST,
  revoke. Entitlement ledger и прежний каталог после очистки остаются прежними.
- Четыре независимых PHP процесса одновременно повторяют запись одного вклада:
  одна запись и один audit, без ошибки уникальности.

Snapshot/restore экспорт включает reward_ledger. Структурная проверка сравнивает
все CREATE TABLE миграций с экспортируемыми таблицами. До live rollout необходимы
приватный snapshot, изолированное восстановление и сохранение старых flags,
аккаунтов, credentials и музыкальной библиотеки.
