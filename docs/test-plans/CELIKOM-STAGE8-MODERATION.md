## Границы Stage 8

**Цель:** реализовать минимальную, закрытую, безопасную server-rendered admin-панель, чтобы администратор мог реально рассмотреть каждый `pending` AudioAsset/Track mapping, прослушать приватный файл, проверить связанный Track, одобрить, отклонить или отключить одобренную версию, увидеть запись решения в audit trail; отдельно обрабатывать заявки **«Предложить песню»**, не содержащие аудиофайл.

**Не делаем:** публичную регистрацию/загрузки (Stage 9–10), trial/payments/referral, Android, автоматическую публикацию, бессмысленную сложную SPA админку, вычислитель audio fingerprint (пока только статус queue), обход прав на распространение.

### Обязательная пользовательская функция «Предложить песню» — ОЧЕНЬ ВАЖНО

Требование утверждено владельцем **в текущем MVP**. Не заменить существующую «Загрузить версию». Два пользовательских сценария:

1. **Загрузить версию:** файл MP3 → rights declaration → pending → админская модерация (существующий Stage 7, публично откроется по установленным gate на Stage 10).
2. **Предложить песню:** пользователь слушает песню в Яндекс Музыке, CELIKOM уверенно обнаруживает текущий `service/Track ID`, артист/название, формирует ссылку на трек. Пользователь нажимает «Предложить песню», **MP3 не нужен**, права на файл подтверждать не требуется, поскольку файла нет. Допустим короткий необязательный комментарий вроде «запикано». Запрос попадает в **отдельную очередь** администратору. Администратор может искать подходящую версию и юридические права на её использование. Отправка предложения НЕ даёт автоматического разрешения на публикацию.

**Где реализуется:** Stage 8 — админская очередь, модель статусов и действия; Stage 10 — публичная кнопка в Chrome popup, auth/rate-limit/anti-spam, endpoint публичного приёма только после соответствующих продуктовых gate. Stage 7 уже создал закрытую таблицу `track_requests` и приватный owner-only POST endpoint: foundation, не готовый публичный сценарий.

## Порядок работ: самостоятельные проверяемые пакеты

**8.0 — аудит состояния и безопасность.** Перед коммитом сверить HEAD, миграции и реальные статусы. Уточнить границы owner-only тестового домена, секреты и безопасное управление админкой. Подготовить слоистую модель доступа. Сначала тесты на disposable `celikom_test*` и синтетических данных, не на настоящем владельческом MP3.

**8.1 — администратор, сессия и audit.** Минимальные `admins`, `audit_log` (или совместимый слой). Пароли безопасно хэшировать, secure/HttpOnly/SameSite cookies, CSRF-token всех write-действий, login throttling, роли, запрет неопознанного доступа, безопасные ошибки. Никогда не хранить пароли/секреты в GitHub/логах/артефактах.

**8.2 — очередь MP3 pending.** Список кандидатов, пагинация/фильтры; service + точный Track ID, title/artist, время, измеренная длительность файла, размер/MIME, SHA-256/dedupe-warning, uploader при наличии идентификатора; приватный аудиоплеер по защищённому маршруту только админу (никаких публичных URL или обхода signed Range policy). Разница между метаданными Yandex-трека и загруженным аудио видима.

**8.3 — транзакционная модерация.** Approve, Reject с причиной, Wrong Track, Bad Quality, Duplicate; disable approved / safely reactivate по согласованной политике. Row locks / optimistic compare для race, ограничение **одной active-approved mapping на Track**, fail-open в расширении, идемпотентность действий; при выключении resolve перестаёт выдавать версию. Нельзя удалить `AudioAsset`, пока на него ссылаются другие Track ID; destructive action с подтверждением и audit. Нельзя одобрять пользовательские файлы автоматически.

**8.4 — отдельная очередь предложенных песен.** Вкладка «Предложенные песни» / `track_requests`: показать `Track ID`, Yandex Music URL, title/artist, дату, статус, необязательный комментарий (если добавляется контрактом), сколько уникальных предложений (по нужной модели, без выдачи персональных данных). Статусы `pending/reviewed/rejected` и административные решения, защита от дублей/rate-limit, ссылки формировать/проверять строго на домене `music.yandex.ru`, а не принимать произвольные URL. Сама заявка ничего не публикует. Можно пометить «уже есть replacement» или связать с очередью MP3.

**8.5 — Reports и Admin Overview/Analytics.** Минимальный report flow, фильтры периода и сводные числа из настоящих таблиц: pending/approved/rejected, объём заявок, ошибки подмен, сколько track requests. Коммерческие показатели не рисовать до появления источников данных. Read-only CSV только admin с логом экспорта и ограничениями размера.

**8.6 — интеграция и проверка безопасности.** GitHub Actions: PHP/SQL tests, upload → pending → approve → resolve/HTTP Range → disable/reject, concurrent moderation, multi-Track shared asset; CSRF, auth, cookie flags, role bypass, login rate limit, directory traversal, asset visibility; закрытая мобильная/десктопная админка. Два независимых Chrome-клиента видят общее approved состояние при одинаковом read-only API access.

**8.7 — владелецкая приёмка.** Дать короткий адрес закрытой админки и понятный вход, без ручного администрирования VPS. С разрешения владельца выбрать реальный `pending` MP3, прослушать/проверить и одобрить/отклонить; проверить его /resolve и оригинальный fail-open. Для «Предложить песню» отдельный ручной Stage8 админский сценарий на синтетическом/непубличном track request. Не включать public uploads.

## Критерии завершения Stage 8 (не компрометировать)

- No-user-pending-in-public: все новые файлы `pending` и не возвращаются `/resolve` до подтверждённого approve.
- Только защищённое действие admin и audit trail изменяют status/is_active.
- Выключение/отклонение не публикует audio, и клиент fallback не блокирует оригинал.
- Нет двойных активных версий при конкуренции; безопасное общее хранение одного AudioAsset.
- Отдельная очередь **«Предложить песню»** реально доступна админу и не содержит обязательного MP3.
- Админ-сессия, CSRF, rate limits и приватность медиа проходят регрессию.
- Шаблоны Chrome пользовательской кнопки Stage 10 остаются **обязательной задачей в карте MVP**, а не скрытым пожеланием.
- Issue #7 не закрывать без фактов; PR #6 не мёржить без разрешения.
