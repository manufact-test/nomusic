# CELIKOM — этап 9: ручная приёмка Chrome 0.4.5

**Состояние на 10.10.2026:** пользовательская авторизация на тестовом Hostinger включена, серверный HTTPS end-to-end тест пройден; расширение 0.4.5 собрано отдельно. Этап 9 **не закрыт** до независимой проверки владельцем реального Chromium. Ниже только Stage 9, не Stage 10.

## Сборка и изоляция

- [Готовый архив ZIP 0.4.5 в GitHub Actions](https://github.com/manufact-test/nomusic/actions/runs/38036567598) (артефакт `celikom-stage9-private-chrome-ffb28374b4e3f97a19aaf3a0cc00724930c686e7`). Внутри artifact ZIP находятся `celikom-extension-0.4.5.zip` и `*.sha256`.
- Проверен SHA-256 готового внутреннего ZIP: `56e87a739b1b7241c11d7702217619e66e3a2d32b8e69104676e5fa1580074d2`. Внутренний ZIP содержит `manifest.json`, `popup/popup.html`, `auth/auth-broker.js`; `api/config.json` указывает на тестовый HTTPS Hostinger.
- Использовать **два независимых тестовых профиля Chrome A и B**. В каждом распаковать `celikom-extension-0.4.5.zip` в отдельный каталог и загрузить **папку с `manifest.json`** через `chrome://extensions` → Режим разработчика → Загрузить распакованное расширение.
- **Не удалять, не обновлять и не заменять рабочую 0.4.4 в существующем профиле**. После установки/включения расширения перезагрузить вкладку Яндекс.Музыки, если она уже открыта.
- Для проверки аккаунтов использовать *отдельный тестовый email и уникальный пароль (≥12 символов)*. На тестовом домене пока **нет подтверждения владения email и восстановления пароля**; не использовать важный пароль от других сервисов.

| ID | Действие | Ожидаемое | Отметка |
|---|---|---|---|

| 9.2 | Проверить пароль короче 12 символов в регистрации (до успешной регистрации, можно использовать другой тестовый email) | Регистрация не отправляется, UI/валидация понятны | ☐ |
| 9.3 | В профиле B войти **в тот же аккаунт**, что в A | Оба профиля показывают один email; установка различается | ☐ |
| 9.4 | В профиле A открыть «Мои устройства» | Видны две активные сессии — «Это устройство» и «Другое устройство» | ☐ |
| 9.5 | Из профиля A нажать «Отключить» для B | Сессия B исчезает из списка; B больше не авторизован после обновления статуса | ☐ |

| 9.8 | В одном профиле отключить интернет, открыть «Аккаунт» и затем восстановить сеть | Локальная сессия сохраняется, после восстановления снова доступна; нет самостоятельного выхода | ☐ |
| 9.9 | Проверить Старт → Стоп → Вернуть оригинал и работу определителя трека на Яндекс.Музыке | Работающий плеер и ранее принятые сценарии этапов 0–8 не сломаны | ☐ |
| 9.10 | В старом рабочем профиле с 0.4.4 повторить штатный Старт/Стоп (без изменения старого расширения) | 0.4.4 продолжает работать как раньше | ☐ |

Важно: открытие «Мои устройства» доступно только в авторизованном аккаунте. «Отключить» завершает выбранную **сессию**, а не удаляет устройство и не блокирует аккаунт. Для проверки 9.5 может потребоваться закрыть/открыть окно popup B. Для теста Spotify/Android ничего менять не нужно.
