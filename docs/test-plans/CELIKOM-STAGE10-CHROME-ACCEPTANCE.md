## Установка без повреждения рабочей 0.4.4

1. Сохранить резервную оригинальную 0.4.4. Если в текущем профиле уже установлена 0.4.7/0.4.8, обновить её НА МЕСТЕ: распаковать `CELIKOM-0.4.10-stage10.zip` поверх той же папки, которая выбрана в Chrome. Открыть `chrome://extensions` и нажать «Перезагрузить» на карточке CELIKOM. Проверить версию **0.4.10**. Не удалять текущую установку: прежний путь сохраняет extension ID, локальную сессию и installation ID.
2. На время проверки в этом профиле должна быть включена только одна версия CELIKOM. Резервную 0.4.4 не удалять; при совпадении профиля временно выключить её. **Перезагрузить вкладку Яндекс.Музыки** после обновления расширения, чтобы убрать старые внедрённые контексты.
3. Войти существующим подтверждённым CELIKOM email и паролем, если сессия не восстановилась автоматически. Повторная регистрация не требуется. Не вводить технические ключи, не копировать storage из 0.4.4, поле тестового Track ID оставить пустым.
4. Отдельный чистый профиль Chrome нужен только для последующей проверки clean install и двух устройств. Он не является отдельным продуктом и не обязателен для первой повторной проверки подмены.

## Главный gate: approved 144530503

1. Открыть и запустить оригинальную песню с **Track ID 144530503**. Проверить, что popup определяет этот же ID. Поле тестового ID оставить пустым.
2. До первого «Старт» обычный login не должен запускать trial. Нажать **«Старт»**: сервер создаёт один trial на **3 суток** для аккаунта, popup показывает срок. Проверить реальную подмену на прежнюю одобренную версию #1, а не только надпись «Подмена активна».

4. **«Вернуть оригинал»** должен вернуть исходную песню. Повторный «Старт» не продлевает trial. **«Стоп»** и выход из CELIKOM должны вернуть оригинал без зависания страницы.
5. На **38436680** и **799133075** подмена отсутствует: оба остаются pending. Не одобрять и не изменять эти записи ради теста.

Проверить возобновление после более 15 минут и перезапуска Chrome: refresh обновляет независимую сессию, её rolling lifetime — 90 дней.
7. При отказе сервера/сети или недоступном аудио должен оставаться/возвращаться оригинал. Не менять системное время или серверные строки trial для проверки трёх суток; expiry проверен в disposable MySQL. Проверка браузерного поведения при настоящем expiry остаётся последующим gate.
