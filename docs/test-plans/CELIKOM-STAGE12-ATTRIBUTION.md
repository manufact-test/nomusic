# Этап 12 — первый пакет приглашений, версия 0.4.12

Issue: https://github.com/manufact-test/nomusic/issues/13

По решению владельца разработка продолжается без выбора платёжной системы.
Зависимость реальной оплаты и условия напоминания зафиксированы в Issue #12.
Этапы 11 и 12 остаются частично выполненными, не закрываются как принятые платежи
или реферальная экономика. Требования этапа 12 сверены с Планом MVP v1.6, стр. 31–32.

## Создано

- Миграция 010: referral_codes (один случайный код на аккаунт) и referrals
  (один пригласивший на приглашённого; запрет self-referral).
- Код создаётся явным POST /api/v1/referrals/code, а не чтением экрана. Повтор,
  независимые устройства и переустановка возвращают тот же код. Персональные
  коды приглашений отделены от будущих campaign/promo кодов.
- GET /api/v1/referrals приватен, требует действующую сессию, возвращает только
  собственный код и число регистраций. Чужие email/ID не раскрываются;
  Cache-Control: no-store, query user_id не определяет аккаунт.
- Необязательный referral_code принимается только при регистрации нового
  аккаунта. При включённой функции создание пользователя, user_registered и
  привязка приглашения выполняются в одной транзакции. Письмо подтверждения
  отправляется после фиксации, как в прежнем email flow. Повторный вход,
  переустановка и смена устройства не изменяют приглашение.
- Экран «Подписка и друзья» внутри аккаунта: реальный срок пробного периода,
  готовность оплаты, число регистраций, создание/копирование кода и системное
  Share при поддержке браузером. Загрузка выполняется при открытии раздела.
- После выхода экран очищается; поздний ответ старого аккаунта не заполняет его
  заново. Данные идут через auth broker, токены в новый UI не возвращаются.
- Поле приглашения при регистрации показывается только при активной функции
  сервера. Когда она выключена, код не теряется молча: запрос с кодом отклоняется
  до создания аккаунта; обычная регистрация остаётся прежней.
- Backup экспорт включает все шесть новых таблиц Stage11/12. Автоматическая
  проверка сопоставляет CREATE TABLE всех миграций со списком snapshot/restore.

## Что не включено

FEATURE_REFERRAL_ATTRIBUTION=0 по умолчанию; нужны миграции перед включением.
Новый код не развёрнут на Hostinger. Рабочий сервер и данные/аудио/модерация не
изменены. 0.4.12 — следующая версия единого расширения с прежними функциями,
не отдельный продукт. Установленную рабочую 0.4.4 не удалять.

Registration не считается qualified paid referral. qualified_count всегда 0,
qualification_available=false, discount_active=false, reward_available=false.
Клиентские paid/qualified/assertions не дают доступ, скидку или награду.
Тестовый адаптер billing не подключён к HTTP и не считается реальным провайдером.
Оплата, отмена и возобновление в UI не предлагаются. Шарится только код,
публичный referral URL не выдумывается до появления реальной страницы регистрации.
