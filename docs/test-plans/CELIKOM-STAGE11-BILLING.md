# Этап 11 — подписка и оплата

Issue: https://github.com/manufact-test/nomusic/issues/11

## Первый пакет: независимая серверная основа

Этап 10 принят владельцем 11.10.2026. Рабочая единая версия — 0.4.11;
пробный период — три дня. Реальные проверки компьютер + Android и окончания
пробного периода перенесены в Issue #10 по решению владельца.

Первый пакет этапа 11 не развёртывается на рабочем сервере. Миграция 009
добавляет четыре таблицы: подписки, события, платежи, корректировки платежей.
В Application нет платёжных маршрутов, выбранного провайдера или регистрации
тестового адаптера. Подписка в EntitlementService включается только явным
параметром; все существующие вызовы используют прежний путь пробного периода.
Версия расширения остаётся 0.4.11. Это развитие одного продукта.

## Контракты и правила

- BillingAdapter описывает создание hosted checkout, изменение продления и
  проверку подписи исходного тела уведомления. Конкретная интеграция ещё не реализована.
- SubscriptionService связывает проверенный аккаунт с внешней подпиской и
  серверной ценой. Ни регистрация подписки, ни возврат из checkout не дают доступа.
- Только проверенное событие `paid` с точными суммой, валютой и периодом создаёт
  платёж и запись entitlement_ledger в одной транзакции.
- Уникальны ID события, платежа и возврата. Повторное уведомление того же платежа
  не увеличивает деньги или срок; подпись проверяется даже у повторов.
- Блокировка аккаунта предшествует блокировке подписки, как при активации
  пробного периода. Одновременные события одного аккаунта сериализуются.
- Отмена продления сохраняет оплаченный период. Запоздалое включение продления
  не отменяет более новое выключение; при равном времени выключение имеет приоритет.
- Неуспешное продление не создаёт доступ. Доступ определяется периодом платежа
  по часам БД, а не строковым статусом подписки; будущий период не закрывает разрыв.
- Частичный возврат сохраняет период; полный возврат или chargeback отзывают
  только соответствующий платёж. Другие платежи и пробный период не отзываются.
- Возврат до получения платежа откатывается и допускает повторную доставку.
  Исходная запись ledger сохраняется для аудита; отзыв хранится у платежа.
- Карточные данные и исходные тела webhook не хранятся; журнал содержит
  нормализованное событие и хеши исходного тела/канонических полей.

## Следующий пакет: требуется выбор платёжной системы

Нужны страна и юридическое лицо получателя денег, страны покупателей и валюта.
После выбора: официальный адаптер, секрет проверки подписи, устойчивое создание
checkout с серверным ключом идемпотентности, сверка подписки и платежа через API
провайдера, повторная обработка/восстановление при потере ответа.

Особенности возврата и chargeback должны быть нормализованы по правилам
провайдера: одно денежное списание не должно учитываться дважды. Восстановление
после выигранного спора, изменение цены, скидки и налоги требуют отдельной
политики; текущая фиксированная серверная цена является контрактом первой основы.

Ещё не выполнены: платёжные HTTP checkout/cancel/resume/webhook маршруты, конкретная
подпись провайдера, интерфейс оплаты/отмены/возобновления, платёжная аналитика,
проверка sandbox и ручная приёмка. Этап 11 остаётся открытым.

Перед развёртыванием нужен актуальный backup и изолированный restore-check.
Рабочая версия, MP3, решения модерации, PR #6 и Issue #7 этим пакетом не меняются.

## Второй пакет: чтение подписки и финансы без провайдера

FEATURE_BILLING_VIEWS=0 по умолчанию; до включения нужна миграция 009.
GET /api/v1/subscription с действующей авторизованной сессией возвращает только
собственные подписки и текущий доступ, Cache-Control: no-store. Внешние ID
платежей/событий/подписки не раскрываются; query user_id игнорируется.
Кнопки pay/cancel/resume выключены; дата следующего списания остаётся null,
поскольку период оплаты не доказывает наличие или расписание автосписания.
Чтение подписки не включает оплаченный доступ в рабочих вызовах EntitlementService.

Раздел админки «Платежи и подписки» доступен только владельцу при том же флаге.
Модератор/наблюдатель получают 403. Отдельно для каждой валюты: поступления,
возвраты, оспаривания, итог после корректировок, число платежей, первые и повторные.
Дата — время подтверждённого события провайдера в UTC; поздняя доставка учитывается
в исходной дате, поэтому исторический отчёт может уточняться. Первым считается
платёж с самым ранним началом периода подписки (при равенстве — меньший ID),
а не самый рано доставленный webhook. Отчёт не складывает валюты и не выдаёт
итог после возвратов за чистую выручку: комиссии провайдера пока неизвестны.
Для USD/EUR/RUB/BYN отображаются дробные суммы; неизвестный масштаб валюты явно
показывается в минимальных единицах и никогда не угадывается.

MRR, разрез цены/скидок, расписание следующего списания и пользовательское
управление оплатой требуют окончательного тарифного/провайдерского контракта.
Тестовые суммы не являются ценой CELIKOM. На рабочем сайте пакет пока не включён.

Проверка второго пакета: код `e27c871dfa6689210c0624bce47853609f05ba1b`,
[CI 38101176015](https://github.com/manufact-test/nomusic/actions/runs/38101176015) — PASS.
Проверены отдельные валюты/частичные возвраты/неизвестные комиссии, приватный
API с чужим user_id, отзыв сессии, Cache-Control, выключенные платёжные действия,
доступ финансов только владельцу и честное пустое состояние. Прошли полная
серверная регрессия, 125 тестов расширения, 17 тестов прототипа и нативный Chrome.
Рабочий сервер и расширение не обновлялись; ручная приёмка нового финансового
