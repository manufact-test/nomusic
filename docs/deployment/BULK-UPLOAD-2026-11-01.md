# Administrative bulk uploads and clear quota errors

Desktop 0.4.67. Owner requested uploading hundreds of songs rather than a ten-attempt ceiling. The existing two verified administrative identity hashes now receive 500 attempts/hour/account, 1000/device and 3000/IP. The database, active status and verified email determine eligibility; client-provided roles, emails, promo codes and identity hashes grant nothing. This changes only the upload quota, not administrative rights, entitlements or diagnostic authority.

Ordinary users keep 10/20/60 account/device/IP protection. Proposals without files retain 20/40/120. The private owner-upload token retains its prior policy. Administrative device/IP buckets use a separate HMAC namespace so bulk activity does not consume ordinary users' shared-IP quota. The stable account bucket remains intact across independent devices and refresh; existing attempts are not erased. All limits remain finite. Fixed server hour buckets remain unchanged; failed attempts still count. The body of a 429 now includes bounded retry_after_seconds and Retry-After. No migrations or resets are needed.

Desktop background errors explicitly name the hourly quota and display the retry time in Europe/Moscow when the server provides it. Starting another attempt immediately clears the previous terminal message. Full upload history is exported only through the existing fresh two-administrator diagnostics gate; public state still excludes it. POST requests are never automatically repeated. File size, rights, format/duration validation, moderation and deduplication remain in force.

The triggering failures 573BC1F5, 38540334 and F79E8A86 were server HTTP 429, not damaged audio or the prior MySQL connection outage. The original owner diagnostics omitted the upload journal; restricted server audit 41307331735 recovered the actual statuses without raw log disclosure.

Validation before delivery: 327 desktop tests; PHP policy tests for exactly two identity hashes and ordinary fallback; disposable-DB tests for unverified/missing users, 500 accepted attempts and rejection of 501/502; full deployment CI, private snapshot/data preservation, HTTPS smoke and read-only verification of live bulk eligibility. Deployment results must be checked before claiming the new server quota is active. Android sources and binaries are outside this change; the additive server upload policy is shared by clients.
