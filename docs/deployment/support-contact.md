# Техподдержка CELIKOM: обращения и ответы

Владелец выбрал форму «Связь с поддержкой» внутри CELIKOM, очередь обращений в админке и ответы из админки. Версия 0.4.30 использует общий API /api/v1/support и существующую SMTP-настройку регистрации. Получатель копии нового обращения — CELIKOM_MAIL_FROM; ответ отправляется на подтверждённую почту аккаунта и сохраняется в переписке. Нового адреса или выбора почтового сервиса не требуется.

Миграция 016 только добавляет support_tickets/support_messages; 001–015 не переписываются. Обращения привязаны к аутентифицированному активному аккаунту. Пользователь видит только все свои обращения и сообщения с пагинацией по 5 записей; owner/moderator видят очередь с пагинацией 20, отвечают и закрывают, viewer доступа не имеет. CSRF обязателен для изменений админки; подготовленные SQL, экранирование текста, ограничение размеров и атомарный лимит 5 новых обращений в час на аккаунт. Идемпотентность по UUID account/request и ticket/request, изменение тела с тем же ключом отклоняется. Черновик/ключ сохраняются в extension session storage до успеха; секреты и полный diagnostic state не отправляются. Данные поддержки включены в backup/restore allowlist.

Сначала транзакция сохраняет обращение/ответ и аудит, затем SMTP вне блокировки. Ошибка почты не теряет переписку. SMTP claim однократный: pending → sending → sent либо unknown. Sent означает, что почтовый сервер принял письмо, а не доказательство доставки в inbox. После неоднозначного результата автоматический повтор письма отключён; повтор HTTP возвращает ту же запись. Проверки используют только изолированный mail_test_sink, писем реальным пользователям тестами не отправляем. Поддержка доступна при истекшем доступе/incident, paid entitlement не требуется. Для проблем входа публичный config показывает валидный существующий MAIL_FROM как запасной контакт.

Форма приложения поступает в БД и админку напрямую; копия уходит на почту. Импорт ответов, отправленных обычным почтовым клиентом, не реализован: SMTP не получает письма. Основной рабочий путь — ответ администратора через админку и чтение пользователем внутри CELIKOM. В диагностический APK без INTERNET форма не добавляется; будущий финальный Android использует тот же API и account.
