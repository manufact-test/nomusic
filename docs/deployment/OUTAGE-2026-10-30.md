# CELIKOM: server outage and desktop recovery, 30 October 2026

## Confirmed incident and limits

At approximately 22:43 Moscow time the public API health, config, admin and root returned HTTP 500 with an empty body. The health response included Hostinger and PHP 8.3.36 headers. At 22:51 health and config returned HTTP 200 again. The owner reported desktop playback returned after refreshing Yandex Music. This proves a server outage and recovery, not its underlying cause. The malware entry supplied by the owner was dated October 10 and belonged to two.manufact.pro, not CELIKOM.

No server application release, database migration, account/session change or Android modification is part of this correction. The separate Android chat continues independently. Do not deploy this branch's server merely to install the desktop fix.

## Desktop 0.4.66

ApiClient and AuthBroker already had bounded GET recovery for network errors and HTTP 502/503/504. HTTP 500 was excluded. The same existing bounded policy now covers HTTP 500, including empty PHP error responses: at most three attempts in a 20-second read deadline, with 500/1000 ms delays. POST requests, including activation, refresh, uploads and payments, are never automatically replayed by this policy.

Original playback remains the fallback. Authority checks remain mandatory: no offline grants, no cached diagnostic permission, no token refresh on transport failure. Existing worker heartbeats retry temporary authorization failure after five seconds; a confirmed allowed response releases suspension. Tests verify recovery without reload/Start/trial activation and preservation of Stop/logout and sender fences. This is fixture evidence, not proof of the exact state of the owner's incident. Popup wording now identifies a server connection problem rather than suggesting the account itself was lost. A failed explicit Start still requires another Start; activation POST is not automatically repeated.

## Monitoring

The old ChatGPT CELIKOM API Health task existed but was disabled; no evidence identifies who disabled it. It was re-enabled with hourly condition checks and alerts only for a confirmed failure or inability to perform monitoring. Hourly checks can miss short outages.

An independent GitHub Actions workflow `CELIKOM API availability` polls health/config/anonymous resolve every five minutes, retries failed samples after three seconds and stores only endpoint names, HTTP statuses, contract results and timings for seven days. No credentials, user data or response bodies are saved. It runs from the default branch, main; only the two monitoring files and their tests are added there, without merging the application branch or triggering a server deployment. GitHub scheduling can be delayed; five minutes is a requested cadence, not a guaranteed detection time. Failure delivery through GitHub depends on the owner's Actions notification preferences. A GitHub-runner edge block is recorded as an unsuccessful external probe, not silently declared healthy. Do not weaken the hosting firewall.

## Read-only cause investigation

`CELIKOM outage read-only audit` uses the existing pinned SSH key/host identity and prints the current release, PHP version, free disk space, entry-file modification times, SELECT 1 result and sanitized error categories/timestamps from bounded log tails for this domain only. Raw logs, errors, config, SQL rows and credentials are never printed. It neither edits server files nor restarts PHP nor applies migrations. Its initial result must be inspected before making any claim about the outage cause. Missing logs or old entries are not a proof of absence of server errors. No new historical log collection can reconstruct errors the host did not retain.

## Validation

Desktop full suite: 324 passing tests. Focused desktop plus monitoring suite: 70 passing tests. Monitoring covers persistent empty 500, recovery, missing JSON feature contract, HTML captive page, oversized response and no credential transmission. Read-only PHP syntax is checked in its workflow because PHP is unavailable in the local workspace. Physical owner acceptance and delivery of real alert notifications remain separate from test success.
