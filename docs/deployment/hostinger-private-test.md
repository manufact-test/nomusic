# Hostinger: закрытый живой тест Stage 5

Пакет Stage 4 подготовлен для PHP 8.3+, PDO MySQL и fileinfo. Это инструкция развёртывания, а не подтверждение уже работающего хостинга. Перед стартом нужны выбранный HTTPS-поддомен API, доступ к панели/SSH и 1–3 проверенных владельцем MP3/WAV. Не передавайте пароли в Git или публичных комментариях.

## Размещение

Для домена с каталогом `domains/DOMAIN/public_html` используйте соседний приватный каталог:

```text
domains/DOMAIN/celikom/releases/0.4.0/   содержимое server ZIP
domains/DOMAIN/celikom/current           ссылка на releases/0.4.0
domains/DOMAIN/celikom/shared/audio/     приватные аудиофайлы
domains/DOMAIN/celikom/shared/env        секретные настройки
domains/DOMAIN/public_html/index.php    копия deploy/public-entry.php
domains/DOMAIN/public_html/.htaccess    копия public/.htaccess
```

В `public_html` попадают только launcher и `.htaccess`. Содержимое ZIP, `.env`, SQL и аудиофайлы остаются вне web root. Если панель позволяет собственный document root, направьте его непосредственно на `celikom/current/public`. Не распаковывайте весь ZIP в `public_html`.

Если уже существует сайт, создайте отдельный поддомен с отдельным корнем. Точные пути и возможность SSH/symlink проверяются по конкретному тарифу, до изменений. При отсутствии symlink можно использовать отдельный приватный каталог `celikom/current` и менять его после проверки нового выпуска; предыдущую копию сохранять для отката.

## Настройки и база

1. Включите PHP 8.3+, PDO MySQL и fileinfo. Создайте отдельную MySQL-базу и пользователя для CELIKOM.
2. Скопируйте `.env.example` в `shared/env`, заполните DB_* и абсолютный STORAGE_PATH. Настройки читаются из `.env` в корне приложения: создайте ссылку `current/.env` на `shared/env` либо приватную копию с правами 0600.
3. Для AUDIO_SIGNING_KEY, API_TEST_TOKEN и ANALYTICS_PRIVACY_KEY создайте **три разных** случайных значения `bin2hex(random_bytes(32))` непосредственно на сервере. Ключи подписи и приватности клиенту не передаются. API_TEST_TOKEN используется только владельцем в закрытом тесте; это временный доступ до этапов аккаунтов/entitlements.
4. Сначала оставьте FEATURE_REPLACEMENTS=0 и FEATURE_ANALYTICS=0. Запустите из приватного каталога выпуска `php bin/migrate.php`. Повторный запуск сверяет checksum миграций и не создаёт дубликаты.
5. Включите действительный SSL и принудительный HTTPS в панели. В PHP отключите display_errors и сжатие динамического аудио. `GET https://API_DOMAIN/api/v1/health` должен вернуть версию 0.4.0; `/api/v1/config` — replacements=false. Health проверяет процесс; успешный resolve отдельно проверяет базу/файл/подпись.
6. Ограничьте запросы к resolve/events средствами хостинга, если они доступны. API_TEST_TOKEN не заменяет клиентскую авторизацию и защиту публичного production API. Access logs с query подписанных URL ограничьте по доступу и сроку хранения; не копируйте их в Git/диагностику. Для публичного запуска понадобится полноценный rate limit и аккаунты по дальнейшему плану.

## Первые файлы

Храните входные файлы в приватном staging. Для каждого файла измерьте длительность, проверьте соответствие оригиналу, начало/конец и разрешение на использование. На Stage 4 автоматической модерации/загрузки через UI нет.

```bash
php bin/import-test-audio.php --file=/PRIVATE/staging/replacement.mp3 --track-id=1944599 --duration-ms=201000 --confirm-reviewed
```

Пример ID/длительности замените фактическими. CLI проверяет MIME, размер и SHA-256, хранит файл под техническим ключом, создаёт exact-ID mapping и переиспользует одинаковый asset. Повторный импорт того же файла/id идемпотентен. Несовпадение длительности более 1.5 s вернёт оригинал в клиенте. Поддержаны MP3/WAV до 30 MiB; поддержка иных кодеков будет проверяться отдельно. Затем включите FEATURE_REPLACEMENTS=1.

## Сборка расширения под домен

```bash
CELIKOM_API_BASE_URL=https://API_DOMAIN npm run build:extension
```

Подставьте реальный origin без пути. Manifest получает разрешение только на этот API origin и Яндекс Музыку. Секретов в сборке нет. После установки/обновления обновите вкладку Яндекс Музыки, очистите тестовый Track ID, в developer details сохраните API_TEST_TOKEN и нажмите «Старт». Пустое поле ID включает серверный каталог; встроенный сигнал остаётся отдельным developer-тестом. Без настроенного API расширение сохраняет оригинал.

## Живой gate

На исходной странице Яндекса подтвердите: mapped ID → реальный файл; немapped ID → оригинал; pause/resume, seek, volume/mute/rate; track change, SPA, reload; «Вернуть оригинал» держится до смены ID или явного «Старт». При отключении API/удалении файла/истечении подписи оригинал возвращается без постоянных повторов. Проверьте 200/206/416/HEAD и byte ranges на реальном HTTPS. Убедитесь, что CSP/автовоспроизведение реальной страницы позволяют этот API origin: CI декодирование на собственном fixture не доказывает это.

Сохраните обезличенную диагностику и результат минимум 2–3 минут активной подмены после seek. Только после этого Stage 5 принят. Истёкшая подпись активного файла возвращает оригинал; нажмите «Старт» для новой попытки. Автоматическое продление длительных paused-сессий требует отдельного сценария.

## Аналитика и откат

Аналитика отключена по умолчанию. После отдельной проверки privacy включите FEATURE_ANALYTICS=1 и ежедневный cron `php cron/aggregate-analytics.php`. Он пересчитывает вчера/сегодня UTC и удаляет сырые события старше ANALYTICS_RETENTION_DAYS (30). UUID событий делает повторы безопасными. Это фундамент счётчиков, не готовая админка или финансовая отчётность.

Откат: FEATURE_REPLACEMENTS=0, вернуть `current` на предыдущий выпуск, восстановить прежний launcher при необходимости. `.env` и аудио остаются shared. Миграции Stage 4 только добавляют таблицы; не удаляйте их при откате. Перед будущими изменениями схемы делайте отдельный backup/restore drill. Для публичного релиза Stage 18 остаётся обязательным.
