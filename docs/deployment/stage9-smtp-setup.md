# CELIKOM — настройка отправителя email для этапа 9.1

Дата: 10.10.2026. **Подготовлено, но не активировано.** Настройка писем — обязательный этап до развёртывания новой регистрации, password reset и будущего trial/billing.

## Что создаёт владелец

**Для текущего бесплатного теста собственный домен и платный почтовый сервис НЕ нужны.** Используйте отдельную бесплатную личную Gmail-почту для исходящих кодов и ваш существующий Proton Mail для приёма пробных писем.

**Временный вариант Gmail:** включить двухэтапную аутентификацию Google и, если функция доступна, создать **пароль приложения**. В настройках указываем SMTP host `smtp.gmail.com`, port `465` (TLS) или `587` (STARTTLS), username и From — полный адрес Gmail, SMTP password — пароль приложения (не основной пароль Google). При вставке удалить пробелы между четырёхзначными группами пароля. Gmail может ограничивать автоматические рассылки и блокировать подозрительную активность; для платного запуска позднее перейти на почту/домен CELIKOM.

**Proton Mail Free** нельзя использовать исходящим серверным SMTP: прямые SMTP-токены требуют платного Proton и адреса на собственном домене, Proton Bridge также платный и работает локально на компьютере. Но Proton подходит как получатель тестовых кодов. Документация: https://proton.me/support/smtp-submission, https://proton.me/support/imap-smtp-and-pop3-setup, https://support.google.com/accounts/answer/185833.

Альтернатива — другой SMTP-провайдер, поддерживающий TLS и отдельные credentials. Отправителю потребуется:

- **SMTP Host** — точное доменное имя сервера исходящей почты;
- **SMTP Port** — 465 (implicit TLS) или 587 (STARTTLS);
- **SMTP Username** — полный логин ящика/SMTP;
- **SMTP Password** — отдельный пароль или app password для SMTP, если поддерживается;
- **From** — проверенный адрес отправителя, например `noreply@...`;
- **Test recipient** — ваш личный адрес для проверки фактической доставки писем.

**SPF, DKIM и DMARC собственного домена** потребуются при переходе на адрес CELIKOM, но **не для временного отправителя @gmail.com**: его почтовые DNS-записи обслуживает Google. Проверять попадание в спам и реальные ограничения отправки всё равно необходимо. Временный Hostinger-субдомен не является почтовым доменом CELIKOM. Не выдавайте ChatGPT пароль или код из письма.

## Как указать реквизиты без передачи секретов в чат

В GitHub откройте репозиторий [manufact-test/nomusic](https://github.com/manufact-test/nomusic) → **Settings → Secrets and variables → Actions → New repository secret**. Добавьте **шесть** новых секретов:

| Secret в GitHub | Что в него указать |
|---|---|
| `CELIKOM_SMTP_HOST` | SMTP-сервер провайдера |
| `CELIKOM_SMTP_PORT` | `465` или `587` |
| `CELIKOM_SMTP_USER` | SMTP login |
| `CELIKOM_SMTP_PASSWORD` | **SMTP пароль** — никому не пересылать |
| `CELIKOM_MAIL_FROM` | Подтверждённый адрес отправителя |
| `CELIKOM_SMTP_TEST_TO` | Адрес для тестового письма |

**Примечание:** всего шесть новых secret-полей; ранее существующий `HOSTINGER_SSH_KEY` уже настроен и не меняется. `CELIKOM_MAIL_CODE_PEPPER` генерируется автоматически на самом Hostinger, сохраняется в приватном `shared/env` и никогда не попадает в GitHub.

После заполнения шести полей сообщите только **«почта создана, секреты добавлены»** (можно отдельно не секретные Host/Port/From). Проверяем [операцию Stage9 SMTP](https://github.com/manufact-test/nomusic/actions/workflows/hostinger-stage9-mail.yml). Внутренняя request-команда в репозитории по умолчанию `prepare`, то есть никакого подключения. Я самостоятельно переключу её в `provision` **после вашего сообщения**, проверю GitHub Actions и сохранность исходной конфигурации.

Пароль передаётся из GitHub Secrets во временную память runner, через зашифрованный SSH-канал на Hostinger, там атомарно записывается в `celikom/shared/env` (0600); создаётся отдельная 0600-копия предыдущей конфигурации. При ошибке TLS/SMTP попытка откатывается. Не публиковать secret в JSON-request, коммитах, issue, скриншотах, Actions-логах или переписке.
