## Что теперь нужно сделать в одном большом рабочем блоке
**A. Массовый импорт.** Параметризовать существующий pipeline на единый запрос 100 или 150, физически грузить 50+50(+50) с автоматическим добором резервных, строгой проверкой файлов, дедупом live DB, исключением pending/approved, журналом ошибок и возобновлением после сбоя. Сначала E2E на тестовом MySQL/хранилище и CI. НЕ запускать очередные 100/150 реальных песен, пока владелец прямо не попросит.

**B. Массовая админка.** В разделе «Загруженные версии» добавить checkbox у pending, «Все 50 на странице», счётчик и три операции — «Одобрить выбранные» (только после явно установленной общей галочки «проверил аудио и права»), «Отклонить» (с причиной), «Удалить» (только owner, отдельное подтверждение, проверка ссылок на аудио и аудит). Сохранить одиночные формы и безопасность (CSRF/role/status locks/race). Проверить 50 записей E2E, интерфейс мобильный/ПК, безопасно выпустить backend отдельной веткой; не делать реального массового approval без решения владельца.

**C. Полная учётная ведомость.** Продолжать CSV из этого handoff, не терять технически неподходящие треки. По окончании всего набора ~1516 source IDs дать владельцу один финальный Excel+CSV всех всё ещё нерешённых ID для ручного поиска, дубли отдельно.
