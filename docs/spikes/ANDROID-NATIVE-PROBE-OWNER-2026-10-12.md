# Проверка native companion на Honor50 — 12.10.2026 МСК

Владелец сообщил Honor50, обновлённый Android и установленную актуальную Яндекс Музыку, точных версий не знает. Согласовал диагностическую сборку для проверки штатного native подключения. Это разрешение на целевую диагностику, не возврат к WebView и не приёмка Stage16/17.

## Поставка

CELIKOM native diagnostic0.3.0-probe, package `pro.celikom.nativeprobe`. Старый WebView0.2.0 (`pro.celikom.spike`) не заменяется и больше не требуется: новая сборка открывает обычную установленную Яндекс Музыку. Это диагностический инструмент, не второй финальный клиент. Нет аккаунтного входа и подмены звука; нет INTERNET/RECORD_AUDIO/MODIFY_AUDIO_SETTINGS. Live backend/extension/data не меняются.

## Шаги владельца

1. Установить APK и открыть «CELIKOM — диагностика».
2. Нажать «Разрешить доступ к уведомлениям» и включить только «CELIKOM: состояние Яндекс Музыки». Сборка фильтрует плеер по `ru.yandex.music`; другие тексты уведомлений не читаются. Android выдаёт широкое системное разрешение; после диагностики его можно отключить. Если система блокирует доступ для установленного APK, штатный пункт «Разрешить ограниченные настройки» может находиться в информации о приложении; не требовать отключения общих защит телефона.
3. Открыть обычную Яндекс Музыку. В её настройках эквалайзера выбрать CELIKOM, если он предложен. Отсутствие выбора — диагностический результат, не повод вводить пароль в ещё одном плеере. Запустить песню, переключить следующую, pause/resume и выключить экран30секунд.
4. Вернуться в диагностику и нажать «Скопировать отчёт», вставить текст в чат. Отчёт включает модель/версии, последнее состояние и ограниченный набор сведений о песне. Интернет/автоотправки нет. Не отправлять пароли или коды входа.

Для независимой проверки exact ID можно отдельно скопировать ссылку на последнюю песню через штатную кнопку «Поделиться» Яндекса. Название/исполнитель и даже числовой MEDIA_ID не считаются точным ID до сверки.

## Что доказывает и чего не доказывает

OPEN/CLOSE с package extra — непроверенные broadcast claims. Реальный panel callingPackage фиксируется отдельно; отсутствующий caller остаётся unverified. Никаких effects на этих events не создаётся. Metadata/state даёт optional MediaSession доступ после пользовательского opt-in; media extras/artwork/raw уведомления не выгружаются. Events bounded30, state timestamp показывает давность, URI userinfo/query/fragment исключены.

Реальная подмена, стабильность session next/seek/quality, безопасный crash recovery, sync/drift, screen-off audio и Bluetooth/car пока НЕ приняты. Наблюдение состояния после screen-off не равно проверке background replacement. Owned audio proof API29/35 run38177741159 остаётся отдельным исследованием. Android35 UI/безопасность harness не выдаётся за проверку самого Яндекса.
