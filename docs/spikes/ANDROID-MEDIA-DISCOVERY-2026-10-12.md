Original0.3.4 public discovery queried only android.media.browse.MediaBrowserService. Its no_public_service result did not prove that modern media services were absent.0.3.8 also queries androidx.media3.session.MediaLibraryService and MediaSessionService. Each query is scoped to the already-visible ru.yandex.music package. GET_SERVICES/MATCH_DISABLED_COMPONENTS manifest inventory distinguishes exported/enabled/unprotected media-action candidates from private, disabled or permission-protected services. Only bounded service names and flags/permission names are reported; no metadata bundles, credentials or session tokens. Up to60 declared rows and3 eligible connection attempts. No binds to arbitrary service classes.

Connection uses the existing standard platform MediaBrowser to an eligible component. Media3's documented legacy bridge can accept platform clients even when the modern action was used for discovery; actual Yandex acceptance is unknown. No client-identity substitution, ungranted permissions, hidden API, source modifications, or transport commands. If the service declines or doesn't implement legacy bridging, the result is retained and no permission bypass is attempted. A dedicated Media3 client may still be needed if discovery reveals such a service.

New diagnostic report retains service_discovery independently of activity teardown so stopped public_browser doesn't erase manifest evidence. Network, notification-listener and microphone remain absent in delivered panelOnly. Same signing certificate. Emulator inventory test covers own package manifest and eligibility; it has no installed real Yandex.
