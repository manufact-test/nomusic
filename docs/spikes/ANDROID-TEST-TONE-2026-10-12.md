0.3.7 preserves the existing attenuation-only button and adds one explicit signal-replacement probe. A finite seven-second,16000Hz mono PCM AudioTrack plays locally generated alternating440/660Hz tones with short gaps and tapered edges, amplitude1200/32768. Its positive audio session must differ from the verified Yandex session. It requests no audio focus and sends no commands to Yandex. The signal is started only after the source-session effect is enabled; any failure releases the signal and original effect. Timeout, stop, session close/change, service destruction and task removal release the signal first, then the original effect. No global mixer changes, network, notification access, microphone or additional permissions.

The synthetic emulator regression checks a separate session, submitted PCM frames and a progressing native playback head; signal/effect release must happen while the activity is closed and UI thread is stalled. It does not establish audibility on the owner's output. Owner should play a song, open Yandex's equalizer, choose the signal probe, return to Yandex, optionally lock the screen, and report whether the original disappeared, the intermittent signal was heard and the original returned automatically. Observe player progress manually; no exact position or play/pause observation is implemented.

This is a bounded manual audio-path test, not exact-track or synchronized song replacement. The old shared_track142820338 remains an explicit link reference. Full automatic track identification and synchronization are still unresolved. No UI product design is being undertaken.
