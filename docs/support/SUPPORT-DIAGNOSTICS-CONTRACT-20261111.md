## Общие обращения Chrome/Brave и Android

POST `/api/v1/support`, обычный действующий customer Bearer, JSON. Активный trial не требуется: поддержка доступна и при окончании подписки.

```json
{
  "kind": "general",
  "message": "Не подключается песня",
  "request_key": "3b043923-1ba6-4829-8ced-672fe422a413",
  "support_diagnostics": {
    "schema_version": 1,
    "platform": "android",
    "version": "0.3.52",
    "diagnostics": {
      "phase": "ERROR",
      "enabled": true,
      "paused": false,
      "currentTime": 12.5,
      "trace": [
        {"event": "backend_http", "endpoint": "resolve", "httpCode": 503, "elapsedMs": 1200, "ageMs": 50}
      ]
    }
  }
}
```

- `platform`: `chromium` для расширения, `android` для согласованного мобильного конверта.
- `version`: только числовая трёхчастная версия, не суффикс тестовой сборки.
- `request_key`: UUID v4; при повторе после неоднозначного ответа сохранять тот же текст и **тот же снимок**. Изменённый payload с прежним ключом отвергается.
- Успех: HTTP 200 и `ticket_id`. Не показывать успешную отправку по одному только завершению прогресса.
- Существующий лимит поддержки — 5 новых обращений в час на аккаунт; точный повтор не создаёт новое обращение.
- UTF-8 сообщение максимум 6000 байт; всё JSON тело максимум 16000. Расширение оставляет вложение не более 6500 байт.
- `track` необязателен: `{id,title,artist,album}`. Не подставлять фиктивный ID, если трек неизвестен.

Сервер повторно применяет белый список из `SongReport::diagnostics()`: известные короткие коды состояния/ошибок; позиции/длительность/счётчики; булевы признаки; ограниченные network и trace. Неизвестные ключи не хранятся. `currentTime`/`duration` — секунды; `durationMs` и поля trace `*Ms` — миллисекунды.

Не отправлять произвольный полный dump: токены, пароли, email, заголовки, файловые пути, аудиоссылки и произвольные логи не входят в этот формат. Для полезных новых полей сначала расширять строгий контракт с тестами, а не засовывать данные в свободные строки.

## Windows W70

Сохранён исходный необязательный `diagnostics` с `platform: windows`, `appVersion`, `nativeModuleVersion`, `yandexVersion`, статусом интеграции и ограниченными `events[{code,ageSeconds,trackId?,resourceId?}]`. Нормализатор `WindowsSupportDiagnostics` взят из W70 и проверен его исходными серверными сценариями. Windows-клиент менять ради нового серверного приёма не требуется, если он уже отправляет этот конверт.

Typed song reports через `kind: song` + `report` сохранены, включая разрешённый Windows trace. Legacy general-сообщения без вложения, с прежним полем `report` или неизвестным старым `diagnostics` других клиентов продолжают приниматься как раньше.

## Админка и приватность

**Техподдержка → обращение → Скачать диагностику JSON.** У обычных обращений отображается платформа. Переписка и отправка ответа прежние; в email уходит только текст, а файл доступен в админке.

GET `/admin/support/diagnostics?ticket=ID` требует owner/moderator-сессию; viewer и обычный Bearer не дают административного экспорта. Заголовки: attachment, no-store, nosniff. В обычном клиентском чтении переписки общий report скрыт (`null`). Вложения хранятся в существующем `report_json`, без публичного файлового адреса и новой миграции.

На живом сервере проверены сохранение и защищённое скачивание всех трёх конвертов. Фактическую отправку из новой мобильной сборки нужно подтвердить с Android-чатом: серверная готовность не означает, что её клиент уже формирует этот payload.

## Сохранность и последующие выкладки

Текущий сервер получен точечным патчем действующего W45, а не заменой всего server из старой ветки. Отдельные изменения CORS и модерации сохранены. Не разворачивать исторический server из клиентской ветки 0.4.76. Источник общего изменения: `feature/server-general-support-attachments-20261111`, PR40.

Реальные аккаунты, trial, подписки, медиа и env не менялись. QA-записи и временные сессии удалены, писем при проверке не отправляли. Платёжные изменения и PR39 не входят в эту выкладку.
