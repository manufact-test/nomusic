# W27 — реальный Windows-тест владельца: AUDIO BLOCKER, диагностики нет (2026-11-09)

Статус: **FAIL / блокер релиза**. Это наблюдение владельца на его Windows, а не результат синтетического CI. Причина мгновенной паузы пока НЕ установлена. Новую рабочую сборку ещё НЕ выпускали; код после W26 не изменён.

## Что было установлено

- Windows CELIKOM Companion 0.24.0, пакет CI 42625065045, artifact 13677423231 (CELIKOM-W24-INTERNAL-NATIVE-UNSIGNED).
- Репозиторий manufact-test/nomusic; ветка experiment/windows-companion-integration-20261108.
- Функциональный SHA W26 7226f1ce595f9ee49781cea50a2ce9d237730503; документационный HEAD до передачи 553ffc73527dd602bd12ba81972a7ddf652bcadc.
- Нативная Яндекс.Музыка 5.126.1 установлена и подтверждена UI как поддерживаемая.
- Владелец прошёл установку CELIKOM, открыл его, подключил модуль («Подключить CELIKOM»), Яндекс закрылся и перезапустился. Отдельный плеер не открывался.
- Владелец открыл свою папку с ранее исправленными цензурированными песнями, в частности «Новогодняя» — Гуф.

## Точный сценарий и наблюдения владельца

1. CELIKOM: подмена выключена («Стоп» уже нажат / отображается «Старт»). В Яндекс.Музыке включается тот же трек — **штатный оригинал играет нормально**.
2. Пока оригинальный трек играет, включить CELIKOM («Старт»). **Оригинал продолжает играть, в середине уже запущенного трека подмена не подключается**.
3. Остановить подмену, снова включить «Старт» и переключить/запустить новый трек в Яндексе. **Воспроизведение как будто начинается и мгновенно переходит в паузу; слушать невозможно**. Владелец отдельно подтвердил симптом на «Новогодней» Гуфа.
4. Отключить подмену — Яндекс снова позволяет нормально воспроизводить оригинальный трек.
5. **Отладочного журнала, выгрузки диагностики и упомянутого владельцем PNR в пользовательском интерфейсе нет.** Пользователю пришлось описывать всё руками. Это отдельный критический дефект UX поддержки.

## Что подтверждено, а что НЕТ

- Подтверждено: установка, native host, renderer hook и запрос /v1/state проходят CI 42625065029; офлайн-тесты 38/38, адаптер 20/20. Проверка реального звука на собственном аккаунте владельца — FAIL.
- НЕ подтверждено: что backend отдаёт именно этому треку разрешённый grant, какой точный Yandex ID использован, успешно ли завершился getFileInfo/getFileInfoBatch, какой ответ получил audio decoder, был ли запрос MP3, есть ли ошибка media pipeline, кто именно инициировал паузу. Не выдумывать причину.
- Проверка «Старт» на уже играющем треке может не приводить к немедленной подмене из-за того, что file-info уже закэширован плеером; это гипотеза, а не диагноз. Мгновенная пауза на новом треке — отдельный серьёзный сбой.
- В исходниках MainWindow.cs НЕТ кнопки «Скачать диагностику». В host.cjs диагностические события пишутся ТОЛЬКО при CELIKOM_W23_DEV_DIAG; в обычной сборке переменная не задана. CI создаёт диагностические файлы в одноразовой машине; в GUI владельца их получить нельзя.
- Интерфейс Windows пока НЕ соответствует дизайну браузерного расширения CELIKOM. Владелец согласился временно отложить визуальное оформление, но требует итоговый паритет UI с расширением.

## Что должен сделать следующий разработчик

**Первый приоритет: встроенная диагностика для обычного владельца, без терминала, ручной настройки и перезапуска с переменными окружения.**

- Кнопка «Скачать диагностику» / «Скопировать диагностику» в окне CELIKOM, доступная при ошибках. Удобный безопасный TXT/ZIP, который можно просто прислать в чат.
- Встроенный bounded event ring buffer и файл с авто-ротацией для Electron main/renderer + локального .NET bridge: версии приложения и Yandex, build SHA, статус интеграции, запрос source по числовому trackId, найден ли grant, выбран оригинал/подмена, тип ответа file-info, результаты попытки HTTP media, media event play/pause/error, причина fallback, переходы Start/Stop/Next/seek, таймауты. Если нет доступа к конкретному событию, НЕ выдумывать его запись; отмечать 'не наблюдается'.
- СКРЫВАТЬ из экспортируемых логов пароли, почты, токены доступа/refresh/bridge, подписанные audioUrl с token/query, cookies, профили Яндекса, содержимое аудио и персональные данные. Допустимы технические коды и trackId, если пользователь сам экспортирует.
- Уточнить фактическое значение термина **PNR** в существующей документации/проекте (владелец прямо просит «диагностику и PNR»); не притворяться, что модуль уже есть, и не подменять термин домыслом.
- После получения настоящей диагностики — выявить точную причину мгновенной паузы и исправить подмену звука **ВНУТРИ** штатного Яндекса, без второго плеера. Затем настоящие Play/Pause/Seek/Next/радио и мгновенная подмена при Start (или честная UI-индикация, если смена только на следующем треке).
- Сначала протестировать на собственном тестовом окружении настолько, насколько позволяет официальный аккаунт, не выдавать синтетический CI за прослушивание; обеспечить повторяемый owner E2E, понятный статус и fallback.
- Перед изменениями — новый backup, сохранять работоспособное отключение подмены и восстановление оригинального Яндекса. Не требовать отключения Defender и не отправлять владельца в терминал.
- Дизайн Windows привести к расширению **после** решения блокера звука и диагностики.
