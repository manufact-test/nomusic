# CELIKOM Windows W184 — 0.24.59 owner delivery (26.11.2026)

## Root cause

Owner W54 from 0.24.58 showed valid grant delivery and a successful native `reloadEntity`, but no `NATIVE_FILEINFO_REQUEST` or player network observation. The source refresh was operating, while the actual Yandex file-info method was not intercepted.

The signed official Yandex 5.128.0 ASAR audit [45839165532](https://github.com/manufact-test/nomusic/actions/runs/45839165532) found:
- module `7123.VE`: current-player state/reload path; `reloadEntity` exists, `getFileInfo` does not;
- module `7695`, export `SonataProvider`: contains the real `getFileInfo` and `getMediaSource` methods.

W183 therefore keeps 7123.VE for current-player observation and reload, but attaches the native adapter to the real 7695 SonataProvider file-info method. It checks the provider's `getFileInfo` and `getMediaSource` shape and fails closed on a pin mismatch. Diagnostics distinguish `RESOURCE_HOOK_ATTACHED_PROVIDER`, legacy endpoint fallback and provider pin mismatch.
