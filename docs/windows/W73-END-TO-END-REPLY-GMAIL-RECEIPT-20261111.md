# W73 — финальная сквозная проверка Windows support → админка → email (11.11.2026)

## Итог: ПОДТВЕРЖДЕНО

Действующая логика поддержки уже совпадает с расширением. **Ни дефекта клиентской отправки, ни дефекта сервера/SMTP по проверенной цепочке не выявлено.** Производство, Windows 0.24.20, расширение 0.4.76 и админку не меняли. Новая Windows-сборка не требуется.

**Фактическая схема:** пользователь Windows отправляет обычное обращение со скрытым JSON → API создаёт ровно один general ticket → owner/moderator видит обращение и может скачать JSON → после ответа администратора сервер посылает email на `users.email` → письмо должно прийти пользователю. На создание обращения не требуется никакой автоматической квитанции пользователю. Для `song` почта не требуется.

## Важные ограничения и безопасность

- Протестирован полный существующий код API/админки/SMTP на **изолированных данных**, но live production DB/UI не загрязнялись новым пользовательским тикетом. Актуальность рабочего сервера/его SMTP проверена отдельным read-only аудитом и реальным inbox реальных уведомлений.

- Новые версии Windows/расширения/сервера не выпускались. Никаких hostinger prod php, prod DB, домена, SMTP секретов, админских ролей, аудио или подписок не меняли. Изменены только приватные CI тесты и документы в Windows ветке.
- В действующем контракте general email-support уведомление отправляется на защищённый адрес поддержки; пользовательское письмо — после ответа администратора. Не добавлять дублирующую автоматическую почтовую квитанцию.
- Продакшн общая поддержка и админка принадлежит актуальной браузерной/серверной ветке; не перезаливать файлы из старого Windows snapshot.
