# W70 — Windows 0.24.18 automatic support diagnostics (2026-11-11)

## Owner request and findings
Owner accepted W69 0.24.17 on his Windows PC. He asks whether every Windows customer support message automatically includes diagnostics, invisible in ordinary user UI, as he remembers doing for Android, so the team can analyze real customer problems. **Before W70: no**. `CompactSendSupportAsync` sent **general text only** using `SendSupportAsync` and **song** report only included numeric track ID, `bridgeStarted` and `enabled`; the richer `DiagnosticLog.ExportText` required owner/developer identity and was not sent through support. No production claim based on Android.

## Architecture implemented, without changing audio/Android
- Isolated working branch: `experiment/windows-w70-auto-support-diagnostics-20261111`; frozen compiled exact W70 source **`3c01da7e9edd4acd2e4f74f3a43801b081c49f1d`**; immutable backup `backup/windows-w70-02418-auto-support-diagnostics-ci-green-20261111`.
- W69 0.24.17 frozen owner-accepted source `da046739d1be008dbc1a9db00bce29ce8867a635` / `backup/windows-w69-02417-uninstall-login-choice-ci-pass-20261110`; **no update** on that branch or current stable Library alias.
- Windows `DiagnosticLog.ExportSupportSnapshot`: on user pressing `Отправить`, bound current last-15-minutes, max **64 entries**, only allowlisted event codes and numeric `trackId`/`resourceId`, app/native/Yandex versions, integration state, Boolean bridge/enable/compatibility flags. No raw log, request URL, signed media token, account email, password, path, HTTP body, exception message or session access/refresh token. Existing staff-only manual diagnostic button/shortcuts still hidden from ordinary clients.
- `CompactPopupActions.CompactSendSupportAsync` adds the private snapshot to **both general** (`diagnostics`) and **song** (`report.diagnostics.windows`) requests; stores the exact attachment per UUID request key for retries, clears on successful response, does not change text, UI, chat replies, or audio behavior.
- `CelikomApi` sends data only over existing signed-in CELIKOM HTTPS Bearer endpoint `POST /api/v1/support`, no separate diagnostic server. A live server running older code may accept requests but will **discard new extra diagnostic fields** until backend upgrade.
- Staged PHP `WindowsSupportDiagnostics::normalize` independently enforces strict allowlist, 900-second age bound, 64 events, numeric identifiers, redacted unknown properties. `SupportService` stores safe report in existing `support_tickets.report_json` (migration 017 already present), with ticket kind still `general` and only customer's original message sent via email. General customer `thread($id,$user)` hides the private report; song typed report preserves a `diagnostics.windows` subsection. Server rate limit, session, UUID retries, admin audit and CSRF unchanged.
- `SupportAdminView` shows **Техническая диагностика Windows** and **Скачать диагностику JSON** for general cases; existing song report download now includes Windows event data. `AdminPanel` only allows owner/moderator download, anonymous login redirect, viewer 403, no public diagnostic URL.
- Version bump Windows to **0.24.18**, original Inno AppId and Yandex/native controls, W69 optional login removal checkbox **all retained**. No edits to Android, browser extension, payment, live Hostinger API or vendor app.
