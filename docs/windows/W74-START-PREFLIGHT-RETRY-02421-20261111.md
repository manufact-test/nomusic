# CELIKOM Windows W74 — исправление ложных ошибок первых нажатий «Старт»

Дата: 11.11.2026. База: принятая Windows **0.24.20** из W72, код `66ffb6348f821416adabb9de4ce110adef1d5b7b`. Новая версия: **0.24.21**, только изменения запуска Windows GUI.

## Реальное сообщение владельца

- Первое нажатие «Старт» показывает модальное «Установленная версия Яндекс.Музыки пока не поддерживается».
- Второе нажатие показывает «Не удалось проверить доступ на сервере. Подмена выключена».
- Третье нажатие предлагает запустить Яндекс; владелец соглашается и работа запускается.
- Версия Яндекса, работающая с третьей попытки, не должна без фактической проверки называться неподдерживаемой.

## Проверенные причины в коде 0.24.20

1. `MainWindow.Shown` начинал `RefreshHostAsync` асинхронно, `StartAction` не дожидался его. При `null` в `_hostReport`/`NotInstalled` в `_nativeInstallState` метод `ConnectYandexAsync` делал неправильный вывод «не поддерживается». Дополнительный `RefreshHostAsync` при уже занятой проверке сразу возвращал управление, вместо ожидания её завершения.
2. `StartAction` имел общий `catch(Exception)`, который абсолютно любой сбой запроса `auth/activate` называл проблемой сервера, не различая временный VPN/timeout, 401/403/429 и прочее.
3. Временный сетевой сбой `auth/activate` не обрабатывался вообще, хотя серверный `TrialService.activate` под блокировкой обеспечивает идемпотентность создания пробного периода.

## Исправления W74

- `RefreshHostAsync` теперь single-flight: все желающие ждут один законченный `RefreshHostCoreAsync`, а не читают полупустые поля; при Start, если проверка ещё идёт, не завершена или старше 2 минут, ожидаем её.
- `StartupHostPreflight.BlockReason` различает `Active` (существующий нативный модуль), `OfficialBaselineVerified` (новая установка), `UnsupportedVersion` (доказанная несовместимость), `InspectionUnavailable` (временная ошибка), `Changed`/`Interrupted` (остановка в целях безопасности). Нет ложного общего модального предупреждения: сообщение в штатном компактном поле.
- `ConnectYandexAsync` теперь `Task`, ожидается из `StartAction`, а не запускается забытым `async void`.
- `StartupActivationRecovery.ActivateAsync` делает ровно 1 повтор `auth/activate` при временном сетевом/5xx/ответе-прокси сбое, с ожиданием 450 мс и ограничением повторного запроса 7 сек. **Никогда** не повторяет при 401, 403, 429, ручном Stop, смене аккаунта или закрытии. Все положительные разрешения только от свежего API-ответа. GET entitlement, клиентский кеш и офлайн-режим никогда не разрешают музыку.
- На реальных отказах нормальные дифференцированные inline-сообщения. Коды сбоев в локальной allowlisted диагностике не содержат токенов и URL.
- `0.24.21` — только GUI, оригинальные native `host.cjs`/`renderer.js` версии **0.24.20** не меняются. `NativeModuleIdentity` проверяет хеши скриптов, а не цифру GUI. Переустанавливать модификацию Яндекса не требуется, если native assets совпадают.
